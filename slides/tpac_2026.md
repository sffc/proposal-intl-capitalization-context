# Capitalization, Titlecasing, and Presentational Case Mapping

## Shane F. Carr (@sffc)
### W3C TPAC 2026 Breakout ([#80](https://github.com/w3c/tpac2026-breakouts/issues/80)) — CSSWG × W3C i18n × TC39-TG2

---

## Three Casing Bugs Shipping on the Web Today

1. **CSS `text-transform: capitalize` on localized dates** (`FullCalendar`, `immich` 70k⭐):
   - Spanish: <span class="str">lunes, 12 de enero de 2026</span> $\to$ ❌ **<span class="str">Lunes, 12 De Enero De 2026</span>**
   - Russian: <span class="str">сентябрь 2026 г.</span> $\to$ ❌ **<span class="str">Сентябрь 2026 Г.</span>**

2. **JS `str.charAt(0).toUpperCase() + str.slice(1)` on non-Latin scripts** (100k+ GitHub files):
   - Georgian: <span class="str">თბილისი</span> (*Tbilisi*) $\to$ ❌ **<span class="str">Თბილისი</span>** *(an ALL-CAPS Mtavruli letter glued onto Mkhedruli — Georgian does not capitalize words!)*

3. **`Intl.DisplayNames` disagrees across browsers** (and all of them are wrong for menus):
   - `new Intl.DisplayNames(['es'], { type: 'language' }).of('es')` $\to$ Chrome: <span class="str">español</span> · Firefox/Safari: <span class="str">Español</span>
   - `new Intl.DisplayNames(['fr'], { type: 'language' }).of('fr')` $\to$ **all** browsers: <span class="str">français</span>

## Untangling Terminology

Standards discussions often stall because **"capitalize"** and **"titlecase"** refer to one of several distinct operations:

| Term | Precise Meaning | Examples |
| :--- | :--- | :--- |
| **Character Titlecase Mapping** | Maps a single letter/digraph according to Unicode titlecase rules (`Lt`) | <span class="str">ǆ</span> $\to$ <span class="str">ǅ</span>, <span class="str">ﬁ</span> $\to$ <span class="str">Fi</span><br/>Dutch <span class="str">ij</span> $\to$ <span class="str">IJ</span>, Georgian <span class="str">ა</span> $\to$ <span class="str">ა</span> (no-op) |
| **First-Word Titlecase** | Apply titlecase mapping to the first \~letter of a string (`titlecase-firstword`, trailing case unchanged) | <span class="str">español de España</span> $\to$ <span class="str">Español de España</span><br/><span class="str">«bonjour»</span> $\to$ <span class="str">«Bonjour»</span> |
| **Sentence Case** | Same as First-Word Titlecase but applied to every sentence in a string | <span class="str">hello world. ¡hola mundo!</span> $\to$ <span class="str">Hello world. ¡Hola mundo!</span> |
| **Every-Word Titlecase** | Apply titlecase mapping to the first \~letter of every \~word in a string (CSS `capitalize`) | <span class="str">español de España</span> $\to$ <span class="str">Español De España</span><br/><span class="str">out-of-the-box</span> $\to$ <span class="str">Out-Of-The-Box</span> |
| **Editorial Title Case** | Same as Every-Word Titlecase but with style guide rules (AP / Chicago / APA) to skip stopwords (<span class="str">of</span>, <span class="str">the</span>, <span class="str">de</span>) | <span class="str">the war of the worlds</span> $\to$ <span class="str">The War of the Worlds</span> |
| **Contextual Capitalization** *(more on this in Part 2)* | Based on a _UI context_ and _category_, choose the correct casing algorithm (`<contextTransforms>`) | <span class="str">septembre</span> (`fr` month) $\to$ <span class="str">Septembre</span> in calendar header, <span class="str">septembre</span> in menu |

## State in the Web Platform

<div class="columns">
<div>

### 1. CSS & HTML
- **`text-transform: capitalize;`** applies *Every-Word Titlecase* to all text. Word boundaries are UA-dependent; **no engine skips stopwords**.
- **`::first-letter`:** block containers only (ignored on inline `<span>`, `<a>`).
- **`<html lang>`** drives CSS casing **but is ignored by JS `toLocaleUpperCase()`**.
- **Open CSS Issues:**
  - [w3c/csswg-drafts#8893](https://github.com/w3c/csswg-drafts/issues/8893) — First-Word / Sentence Case
  - [w3c/csswg-drafts#12526](https://github.com/w3c/csswg-drafts/issues/12526) — Editorial Title Case

</div>
<div>

### 2. JavaScript (`String` & `Intl`)
- **No native titlecase mapping** (`toUpperCase()` / `toLowerCase()` only).
- **`Intl` formatters** return a single default casing with **no UI context option**.
- **Open JS / `Intl` Issues:**
  - [tc39/ecma402#294](https://github.com/tc39/ecma402/issues/294) — Titlecase / Case Mapping in JS
  - [tc39/ecma402#355](https://github.com/tc39/ecma402/issues/355) — Contextual Capitalization in `Intl`

</div>
</div>

# Part 1: Bugs & Gaps in Applying Titlecase
## Why Naive JS & CSS Workarounds Fail Across Scripts

---

## The Ubiquity of Naive First-Letter Uppercase in JS

Because JavaScript lacks a titlecase primitive ([tc39/ecma402#294](https://github.com/tc39/ecma402/issues/294)), the entire ecosystem copies one broken snippet:

```js
const capitalize = (s) => s.charAt(0).toUpperCase() + s.slice(1);
```

- **100,000+ public GitHub files** hardcode it; [Stack Overflow #1026069](https://stackoverflow.com/questions/1026069) recommends it to **4.7M+ viewers**.
- **Baked into the platform's neighbors:** TypeScript intrinsic `Capitalize<S>`, Vue (`@vue/shared`), MUI, Angular, Lodash `_.upperFirst`.
- **i18n maintainers tell developers to write it:** FormatJS ([#1527](https://github.com/formatjs/formatjs/issues/1527)), Moment.js, and `date-fns` advise post-processing formatted dates with `s[0].toUpperCase() + s.slice(1)`.
- **Zero locale awareness:** **0 out of 563** sampled call sites pass a locale to `toLocaleUpperCase(locale)`.

<!--
- SO question: "How do I make the first letter of a string uppercase in JavaScript?" — 4,500+ upvotes.
- TypeScript implements Capitalize<S> inside the compiler as s.charAt(0).toUpperCase() + s.slice(1).
- The 563-hit sample = 400 real call sites + 163 helper definitions (details in Part 3).
-->

## Failure 1: Wrong Mapping — Titlecase $\neq$ Uppercase

`toUpperCase()` applies `Uppercase_Mapping`; a first letter needs `Titlecase_Mapping` **plus locale tailorings**:

- **Digraphs & ligatures:** <span class="str">ǆep</span> $\to$ **<span class="str">ǅep</span>** (not ❌ <span class="str">Ǆep</span>); <span class="str">ﬁrst</span> $\to$ **<span class="str">First</span>** (not ❌ <span class="str">FIrst</span>)
- **Greek (`el`):** <span class="str">άνθρωπος</span> $\to$ **<span class="str">Άνθρωπος</span>** — titlecase keeps the initial *tonos*; uppercase strips it (<span class="str">ΑΝΘΡΩΠΟΣ</span>)
- **Turkish / Azeri (`tr`/`az`):** <span class="str">istanbul</span> $\to$ **<span class="str">İstanbul</span>** (not ❌ <span class="str">Istanbul</span>)
- **Dutch (`nl`):** <span class="str">ijsland</span> $\to$ **<span class="str">IJsland</span>** — the tailoring spans two code units, so even `str[0].toLocaleUpperCase('nl')` yields ❌ <span class="str">Ijsland</span>
- **Georgian (`ka`)** *(from the opening slide)*: titlecase is the identity; uppercase produces Mtavruli ❌ <span class="str">Თბილისი</span>

<!--
More SpecialCasing.txt examples:
- Armenian "ևս" -> "Եւս" (not "ԵՒս")
- Greek polytonic "ᾳδης" -> "ᾼδης" (not "ΑΙδης")
-->

## Failure 2: Wrong Index — `str[0]` Is Not "the First Letter"

- **UTF-16 surrogates (9 bicameral non-BMP scripts):** In **Adlam** (<span class="str">𞤢𞤤𞤢𞤲𞤣</span> *Sunday*), Deseret, Osage, Warang Citi, `str[0]` is a lone high surrogate — `toUpperCase()` is a **silent no-op** ([sindresorhus/camelcase#117](https://github.com/sindresorhus/camelcase/issues/117)); JSX drop-cap splits tear the pair into **`U+FFFD U+FFFD`**.
- **Combining marks:** Slicing NFD Lithuanian `"i\u0307\u0303"` separates the base from its marks: ❌ <span class="str">İ̃</span>.
- **Leading punctuation & Bidi isolates:** <span class="str">¿cómo estás?</span>, <span class="str">«bonjour»</span>, and Fluent's `"\u2068lundi\u2069"` all uppercase a non-letter at index `0`.
- **"Skip to the first cased character" is wrong too:** <span class="str">49ers</span> $\to$ ❌ <span class="str">49Ers</span>; Dutch <span class="str">'s-Gravenhage</span> $\to$ ❌ <span class="str">'S-Gravenhage</span>.

<!--
- JSX pattern: <span>{str[0].toUpperCase()}</span>{str.slice(1)} — the high and low surrogate end up in different DOM text nodes.
- Project Fluent wraps interpolated terms in FSI/PDI (U+2068/U+2069) isolates by default.
- 's-Gravenhage: the elision prefix stays lowercase and the following word is already capitalized; correct output is unchanged input.
-->

---

## Failure 3: Wrong Scope — `\b\w` and `.slice(1).toLowerCase()`

1. **ASCII-only RegExp** (`str.replace(/\b\w/g, c => c.toUpperCase())`): in JS, `\b` and `\w` match only `[A-Za-z0-9_]` — even with `/u` ([angular/angular#23267](https://github.com/angular/angular/issues/23267)):
   - <span class="str">février</span> $\to$ ❌ **<span class="str">FéVrier</span>**; <span class="str">don't</span> $\to$ ❌ **<span class="str">Don'T</span>**; <span class="str">l'arbre</span> $\to$ ❌ **<span class="str">L'Arbre</span>**

2. **Lowercasing the tail destroys inner case** (`w[0].toUpperCase() + w.slice(1).toLowerCase()`):
   - <span class="str">COVID-19</span> $\to$ ❌ **<span class="str">Covid-19</span>** ([angular/angular#41420](https://github.com/angular/angular/issues/41420)); <span class="str">iPhone</span> $\to$ ❌ **<span class="str">Iphone</span>**
   - <span class="str">María José</span> $\to$ ❌ **<span class="str">María josé</span>**; <span class="str">McDonald</span> $\to$ ❌ **<span class="str">Mcdonald</span>**

<!--
More: "éclair" -> "éClair"; "FOGÃO" -> "FogãO"; "Español de España" -> "Español de españa"; "van der Berg" -> "Van Der Berg".
-->

---

## What a Correct First-Word Titlecase Needs

1. **Unicode `Titlecase_Mapping` + locale tailorings** — not `Uppercase_Mapping` *(Failure 1)*
2. **Operate on the string, not on index 0** — surrogates, combining marks, digraphs *(Failure 2)*
3. **Leading adjustment:** skip <span class="str">«</span> <span class="str">¿</span> quotes and Bidi isolates, but keep <span class="str">49ers</span> and <span class="str">'s-Gravenhage</span> intact
4. **Trailing case unchanged:** preserve <span class="str">MacDonald</span>, <span class="str">iPhone</span>, <span class="str">España</span>, <span class="str">COVID-19</span> *(Failure 3)*

> ICU4C (`U_TITLECASE_WHOLE_STRING | U_TITLECASE_NO_LOWERCASE`) and ICU4X (`TitlecaseMapper`, `LeadingAdjustment::Auto`, `TrailingCase::Unchanged`) already implement all four. **No new algorithm is needed — only a way to reach it from the web platform.**

Meanwhile, `s[0].toUpperCase() + s.slice(1)` stays exactly right for one job: **ASCII identifiers** (`on${cap(event)}`). More in Part 3.

## CSS: `capitalize` Is the Wrong Algorithm, and `::first-letter` Can't Help

<div class="columns">
<div>

### 1. `capitalize` Forces Every-Word Casing
**1.7M+ CSS/TSX/Vue files** apply `text-transform: capitalize`; in 1,000 sampled fragments it lands on translated headings, weather, dates, and language pickers:
```html
<h2 class="text-capitalize">{{ $t('our_services') }}</h2>
<span class="capitalize">{{ weather.description }}</span>
```
- <span class="str">nos services numériques</span> $\to$ ❌ **<span class="str">Nos Services Numériques</span>**
- <span class="str">cielo claro</span> $\to$ ❌ **<span class="str">Cielo Claro</span>** *(1,908 weather files)*

</div>
<div>

### 2. Why `::first-letter` Doesn't Save Us
```css
.label::first-letter { text-transform: uppercase; }
```
- **Block containers only** (`CSS Pseudo-Elements 4 §2.2`): ignored on inline `<span>`, `<a>`, `<label>`.
- **`uppercase` $\neq$ titlecase:** strips Greek *tonos*, produces Georgian Mtavruli.
- **Engine bugs** with `::first-letter { text-transform: capitalize }`: Dutch <span class="str">ijsland</span> $\to$ ❌ <span class="str">Ijsland</span> ([crbug.com/1172333](https://crbug.com/1172333)); `"«\u00A0bonjour"` ([crbug.com/41270370](https://crbug.com/41270370)).

</div>
</div>

## CSS Casing Leaks Out of the Visual Layer — and Can't Reach Everywhere

1. **Screen readers** ([w3c/accname#239](https://github.com/w3c/accname/issues/239), [w3c/csswg-drafts#10732](https://github.com/w3c/csswg-drafts/issues/10732)): `text-transform` leaks into the accessible name.
   `<button style="text-transform: uppercase">Call us</button>` $\to$ announced as ❌ **<span class="str">Call U.S.</span>**

2. **Clipboard & `element.innerText`** ([webkit.org/b/43202](https://bugs.webkit.org/show_bug.cgi?id=43202)): presentational casing is baked into copied text and application state.

3. **Non-CSS surfaces:** `<title>`, `<option>` in native `<select>`, `aria-label`, `<canvas>` / WebGL text, Web `Notification` payloads — CSS cannot style these strings at all.

# Part 2: Contextual Capitalization
## Even With a Good Titlecase Algorithm, *When* Should You Apply It?

---

## Capitalization According to CLDR and Unicode

<div class="columns">
<div>

### Phase 1: Contextual Decision

**Input:** Locale, UI Context, Lexical Category
**Output:** Algorithm Choice *(via CLDR `<contextTransforms>`)*

_Example UI Contexts (`UTS #35` + UI):_
- **Middle of sentence** (`middle-of-sentence` — CLDR default)
- **Beginning of sentence** (`beginning-of-sentence`)
- **Menu / list item** (`uiListOrMenu`)
- **Standalone label / header** (`stand-alone`)

_Example Lexical Categories:_
- **CLDR nouns:** Month/day name, Language/region name, Relative date (<span class="str">yesterday</span>), Currency/unit
- **Person name** (always `no-change`)
- **Prose / UI label** (no CLDR data — the author decides)

</div>
<div>

### Phase 2: Case Map Execution

**Input:** Locale, String, Algorithm Choice
**Output:** Case-Mapped String *(Part 1!)*

_Algorithm Choices:_
- **`no-change`** *(mid-sentence, Swedish standalone months, French menu months, person names)*
- **First-Word Titlecase** (`titlecase-firstword`)
- **Sentence Case** (First-Word per `UAX #29` sentence)
- **Every-Word Titlecase** (per `UAX #29` word — CSS `capitalize`)
- **Editorial Title Case** (Every-Word minus stopwords)

</div>
</div>

<!--
Implementation notes:
- titlecase-firstword = ICU4X TitlecaseMapper::titlecase_segment / ICU4C U_TITLECASE_WHOLE_STRING with TrailingCase::Unchanged and LeadingAdjustment::Auto — zero BreakIterator cost.

- "Headline / Title" is an additional editorial UI context not in CLDR.

## Why Unconditional First-Word Casing Fails (`<contextTransforms>`)

Developers who notice CSS `capitalize` hits every word switch to JS and hardcode **First-Word Casing for every locale and UI slot**:

```js
const s = date.toLocaleDateString(locale, { month: 'long', year: 'numeric' });
return capitalizeFirstWord(s, locale); // ❌ Runs for EVERY locale & UI context!
```

| Item & UI Context | Spanish (`es`) | French (`fr`) | Czech (`cs`) | Swedish (`sv`) / Finnish (`fi`) |
| :--- | :---: | :---: | :---: | :---: |
| **Month in Calendar Header (`stand-alone`)** | <span class="str">Septiembre</span> (Cap) | <span class="str">Septembre</span> (Cap) | **<span class="str">září</span> (`no-change`)** | **<span class="str">september</span> / <span class="str">syyskuu</span> (`no-change`)** |
| **Month in `<select>` Menu (`uiListOrMenu`)** | <span class="str">Septiembre</span> (Cap) | **<span class="str">septembre</span> (`no-change`)** | <span class="str">Září</span> (Cap) | **<span class="str">september</span> / <span class="str">syyskuu</span> (`no-change`)** |
| **Language in `<select>` Menu (`uiListOrMenu`)** | <span class="str">Español</span> (Cap) | <span class="str">Français</span> (Cap) | <span class="str">Čeština</span> (Cap) | <span class="str">Svenska</span> / <span class="str">Suomi</span> (Cap) |
| **Language Standalone (`stand-alone`)** | <span class="str">Español</span> (Cap) | **<span class="str">français</span> (`no-change`)** | <span class="str">Čeština</span> (Cap) | <span class="str">Svenska</span> / **<span class="str">suomi</span> (`no-change`)** |
| **In Running Text (`middle-of-sentence`)** | **<span class="str">septiembre</span>** | **<span class="str">septembre</span>** | **<span class="str">září</span>** | **<span class="str">september</span> / <span class="str">syyskuu</span>** |

**Bold** = where unconditional First-Word Titlecase produces the *wrong* answer.

## Why `Intl` Is Inconsistent Today

- **CLDR stores terms in middle-of-sentence form** (<span class="str">enero</span>, <span class="str">janvier</span>, <span class="str">español</span>, <span class="str">русский</span>) and uses `<contextTransforms>` to adjust for UI contexts.
- **ECMA-402 never exposed the context** ([tc39/ecma402#355](https://github.com/tc39/ecma402/issues/355)), so each engine picked one:
  - **V8 (Chrome):** `UDISPCTX_CAPITALIZATION_NONE` $\to$ <span class="str">español</span>
  - **SpiderMonkey & JSC:** `UDISPCTX_CAPITALIZATION_FOR_STANDALONE` $\to$ <span class="str">Español</span>
- **Even `STANDALONE` isn't what a menu wants:** CLDR `fr`, `fi`, `da` capitalize languages only in `uiListOrMenu` $\to$ <span class="str">français</span> in every browser.
- **Production pain:**
  - **Perplexity language picker** ([#355](https://github.com/tc39/ecma402/issues/355)): of ~50 interface languages in Chrome, **27 lowercase** (<span class="str">español</span>, <span class="str">polski</span>, <span class="str">čeština</span>) and **~23 capitalized** (<span class="str">English</span>, <span class="str">Deutsch</span>, <span class="str">Türkçe</span>).
  - **Project Fluent** ([#299](https://github.com/projectfluent/fluent/issues/299)) and **FormatJS** ([#1527](https://github.com/formatjs/formatjs/issues/1527)) declined to add casing filters, pointing to [#355](https://github.com/tc39/ecma402/issues/355) as the missing primitive.

### Study Scope
- **563 JS hits** of `s.charAt(0).toUpperCase() + s.slice(1)` (**400 real call sites** + 163 helper defs), each classified by *what* is being capitalized
- **~190 localized `Intl` call sites**, **1,000 CSS `.capitalize` fragments**, **2,000+ i18n lines**

### Headline Findings
- **93.5%** leave trailing characters untouched (no `.toLowerCase()`).
- **33% of Vue `$t()` + `.capitalize`** and **25–30% of CSS date/calendar** hits misuse CSS `capitalize` because the platform lacks First-Word Titlecase and `Intl` context.
- **Each wedge wants a different fix** $\to$ next five slides.

## Wedge 1 — UI Labels & Translated Strings (50.5%)

**What:** status chips (<span class="str">in progress</span>), tabs, table headers, `$t('our_services')` $\to$ <span class="str">nos services numériques</span> — *202 JS sites + 33% of Vue `.capitalize` uses*

**Today:** `s[0].toUpperCase() + s.slice(1)` *(Failures 1–2)* or CSS `capitalize` *(❌ <span class="str">Nos Services Numériques</span>)*

**Better — Phase 2 only.** The author already made the Phase 1 decision ("this label is First-Word / Sentence Case"); the platform just needs to execute it correctly:
- **In the DOM:** declarative first-word / sentence `text-transform` — [w3c/csswg-drafts#8893](https://github.com/w3c/csswg-drafts/issues/8893)
- **Outside CSS / in i18n pipelines:** a JS single-span primitive — [tc39/ecma402#294](https://github.com/tc39/ecma402/issues/294); MessageFormat 2 function — [message-format-wg#38](https://github.com/unicode-org/message-format-wg/issues/38)

---

## Wedge 2 — Code & Identifier Generation (25.8%)

**What:** `on${cap(event)}`, `set${cap(prop)}`, PascalCase conversions — *103 JS sites*

**Today:** `s.charAt(0).toUpperCase() + s.slice(1)`

**Better — nothing to change.** Programmatic identifiers are locale-insensitive ASCII by design. This is the **one place the idiom belongs**.

> **Lesson for API design:** a new primitive must not be sold as a drop-in replacement for *all* uses of the idiom — a quarter of them are correct as-is. Naming matters (`toLocaleCapitalize` vs. `capitalize`).

---

## Wedge 3 — API / DB Phrases, Error Toasts & Prose (14.8%)

**What:** `weather[0].description` $\to$ <span class="str">cielo claro</span>, `toast.error(err.message)`, free-text headings — *59 JS sites; 1,908 weather files; 106 Go/Rust error-string files*

**Today:** First-Word idiom (10.8%, *Failures 1–2*), `\b\w` regex (4.0%, *Failure 3*), or CSS `.capitalize` (❌ <span class="str">Cielo Claro</span>)

**Better — Phase 2 in JS** ([tc39/ecma402#294](https://github.com/tc39/ecma402/issues/294)):
- **First-Word:** `str.toLocaleCapitalize(locale)` with `trailingCase: 'unchanged'`, `leadingAdjustment: 'auto'` defaults
- **Editorial Title Case:** compose [#294](https://github.com/tc39/ecma402/issues/294) with `Intl.Segmenter` in userland — stopword lists stay out of the engine

---

## Wedge 4 — Person & Place Names (6.5%)

**What:** `nombre`, `prenom`, `isim` form fields — *26 JS sites, the **only** slice that also calls `.toLowerCase()`*

**Today:** `w[0].toUpperCase() + w.slice(1).toLowerCase()` $\to$ ❌ <span class="str">María josé</span>, ❌ <span class="str">Mcdonald</span>, ❌ <span class="str">Van Der Berg</span>

**Better — `no-change`.** Never case-normalize personal names.
- For initials and monograms, use UTS #35 Part 8 `initialPattern` (`Intl.PersonNames`) on grapheme clusters.

---

## Wedge 5 — `Intl` & Date-Library Outputs (2.5% of JS, 25–30% of CSS date hits)

**What:** `toLocaleDateString`, `Intl.DisplayNames`, `RelativeTimeFormat` results — *10 random JS sites, ~190 localized sites, the bulk of CSS calendar/date `.capitalize`*

**Today:** `cap(date.toLocaleDateString(loc, …))` — **unconditional**, so Swedish/Finnish months become ❌ <span class="str">September</span> and French menu months ❌ <span class="str">Septembre</span>; CSS `.capitalize` on headers gives ❌ <span class="str">Lunes, 12 De Enero</span>

**Better — Phase 1 + Phase 2 inside `Intl`** ([tc39/ecma402#355](https://github.com/tc39/ecma402/issues/355)):
- `{ capitalization: 'standalone' | 'ui-list-or-menu' | 'beginning-of-sentence' }` on `Intl` formatters — only `Intl` knows it is formatting a *month* vs. a *language*
- **Co-requisite:** audit missing CLDR `<contextTransforms>` (`pt` months, `pl`/`hu` languages, `fr`/`es` relative)

## Architecture: Which Layer Owns Which Phase?

| Layer | **Phase 1 — Who decides the algorithm?** | **Phase 2 — What it applies** | Issue |
| :--- | :--- | :--- | :--- |
| **CSS `text-transform`** | The **author**, per element | Every-Word today; **First-Word / Sentence** proposed | [#8893](https://github.com/w3c/csswg-drafts/issues/8893) |
| **JS `String`** | The **author**, per call | **Single-span First-Word** (proposed) | [#294](https://github.com/tc39/ecma402/issues/294) |
| **`Intl` formatters** | **CLDR `<contextTransforms>`** — locale × UI context × *lexical category* | First-Word on the formatted noun | [#355](https://github.com/tc39/ecma402/issues/355) |
| **Userland libraries** | A **style guide** (AP / Chicago) | Editorial Title Case via `Intl.Segmenter` + [#294](https://github.com/tc39/ecma402/issues/294) | — |

- **Only `Intl` can do Phase 1 for CLDR nouns:** in a French menu a *language* is capitalized (<span class="str">Français</span>) but a *month* is not (<span class="str">septembre</span>). CSS and `String` only see <span class="str">"septembre"</span>.
- **For ~90% of call sites (Wedges 1–3) the author *is* Phase 1** — they only need a correct Phase 2.
- **"Shouldn't this just be CSS?"** CSS can't reach `<title>`, `<option>`, `aria-label`, `<canvas>`, MF2; inline `<span>` sentence scope is ambiguous; and it leaks into `accname` and the clipboard.

## Track 1: Sentence / First-Word Casing in CSS ([#8893](https://github.com/w3c/csswg-drafts/issues/8893))

**Goal:** a declarative `text-transform` value that applies First-Word / Sentence Case (`Titlecase_Mapping`, trailing case unchanged, leading adjustment) to the start of a text scope instead of every word — fixing <span class="str">Nos services numériques</span> and <span class="str">Cielo claro</span> without `display: inline-block` `::first-letter` hacks.

### The question for CSSWG: what is the "text scope" for an inline element?

```html
<p>See <span class="first-word">our guide</span> to <span class="first-word">cats</span>.</p>
```
An inline `<span>` may be a full label, sit mid-sentence, or hold half a sentence. *(This is why `::first-letter` was restricted to block containers!)*

Also open: multi-sentence mode needs `UAX #29` sentence breaks (<span class="str">Dr. Smith</span> false positives); Editorial Title Case stopwords ([#12526](https://github.com/w3c/csswg-drafts/issues/12526)) are style-guide-specific and arguably belong in userland (cf. `@text-transform` [#3132](https://github.com/w3c/csswg-drafts/issues/3132)).

## Track 2: Contextual Capitalization in `Intl` ([#355](https://github.com/tc39/ecma402/issues/355))

For CLDR nouns (`DateTimeFormat`, `DisplayNames`, `RelativeTimeFormat`), expose `{ capitalization }` so `Intl` executes **Phase 1 (`<contextTransforms>`) + Phase 2 (`titlecase-firstword`)**:

```js
// 1. Standalone calendar header:
new Intl.DateTimeFormat(locale, {
  month: 'long', year: 'numeric',
  capitalization: 'standalone',
  // 'middle-of-sentence' (default) | 'beginning-of-sentence' | 'ui-list-or-menu' | 'standalone'
}).format(date);
// es -> "Septiembre de 2026"   (first word titlecased, "de" stays lowercase!)
// sv -> "september 2026"       (respects Swedish no-change rule!)

// 2. Language picker menu:
new Intl.DisplayNames([locale], { type: 'language', capitalization: 'ui-list-or-menu' }).of('es-ES');
// fr -> "Espagnol d’Espagne"   (capitalized in menus, lowercase in running text)
// es -> "Español de España"
```

- **Resolves the Chrome vs. Firefox/Safari divergence** by standardizing `'middle-of-sentence'` as the default while giving UI authors explicit control.

## Track 3: Single-Span Case Mapping Primitive in JS ([#294](https://github.com/tc39/ecma402/issues/294))

For the **90%+ of JS human-text call sites** that transform non-`Intl` strings (Wedges 1 & 3):

```js
// Direct Phase 2 replacement for s.charAt(0).toUpperCase() + s.slice(1)
// Defaults: trailingCase: 'unchanged', leadingAdjustment: 'auto'
str.toLocaleCapitalize(locale);
// "cielo claro" ('es')     -> "Cielo claro"
// "«bonjour»" ('fr')       -> "«Bonjour»"
// "\u2068lundi\u2069"      -> "\u2068Lundi\u2069"
// "ijsland" ('nl')         -> "IJsland"
// "'s-Gravenhage" ('nl')   -> "'s-Gravenhage"
// "თბილისი" ('ka')         -> "თბილისი" (no-op!)
```

- **Zero word segmentation** — no `BreakIterator`, no `UAX #29` edge cases; maps 1:1 onto `U_TITLECASE_WHOLE_STRING` / ICU4X `titlecase_segment`.
- **Composes with `Intl.Segmenter`** for ~1 KB userland Editorial Title Case *(Appendix A3)*.
- **Name TBD** — deliberately *not* `titleCase`, to avoid confusion with multi-word Editorial Title Case.

## A1: CSS Tailoring Interop, Performance & Leaks

Even for existing `text-transform` values, browsers need alignment on Phase 2 execution and accessibility:

1. **Zero-regression engine fast path** ([crbug.com/420998400](https://crbug.com/420998400), [crbug.com/41248541](https://crbug.com/41248541)): when Blink switched `capitalize` to ICU `CaseMap::toTitle` to fix Dutch <span class="str">IJ</span>, per-run `BreakIterator` instantiation caused a **4.3% Speedometer 3 regression**. Cache `BreakIterator` per locale for every-word `capitalize`; use zero-breaker single-span titlecasing for first-word transforms.

2. **Align locale tailorings & word boundaries:** Dutch <span class="str">IJsland</span> and <span class="str">'s-Gravenhage</span> (incl. `::first-letter`, [crbug.com/1172333](https://crbug.com/1172333)); Irish (`ga`) prefix mutations (<span class="str">an t-uisce</span> $\to$ <span class="str">AN tUISCE</span>, currently Gecko-only); `UAX #29` on <span class="str">foo.bar</span> and Catalan <span class="str">cancel·lar</span>.

3. **Stop accessibility & clipboard leaks:** [w3c/accname#239](https://github.com/w3c/accname/issues/239), [w3c/csswg-drafts#10732](https://github.com/w3c/csswg-drafts/issues/10732), [webkit.org/b/43202](https://bugs.webkit.org/show_bug.cgi?id=43202).

## A2: `Intl.DisplayNames` Engine Divergence in Detail

```js
new Intl.DisplayNames(['es'], { type: 'language' }).of('es');
// Chrome:         "español" (lowercase)   — V8 passes UDISPCTX_CAPITALIZATION_NONE
// Firefox/Safari: "Español" (Capitalized) — SpiderMonkey & JSC pass UDISPCTX_CAPITALIZATION_FOR_STANDALONE

new Intl.DisplayNames(['fr'], { type: 'language' }).of('fr');
// ALL browsers:   "français" (lowercase!)
// Why? CLDR 'fr' (and 'fi', 'da') only capitalizes languages in uiListOrMenu, not stand-alone!
```

- ICU compiles `<contextTransforms>` into a 2-bit flag vector per category, so honoring the context costs nothing at format time.
- In ICU4C (`reldatefmt.cpp:816`), `RelativeDateTimeFormatter` only checks `CAPITALIZATION_FOR_BEGINNING_OF_SENTENCE` and ignores `STANDALONE` and `UI_LIST_OR_MENU`.

## A3: Resolving the July 2020 TC39-TG2 Objections to [#294](https://github.com/tc39/ecma402/issues/294)

1. ***"Shouldn't this just be done in CSS?"*** — See Architecture slide: non-CSS sinks, MF2, inline-span ambiguity, `accname` / clipboard leaks.
2. ***"What about <span class="str">MacDonald</span> and <span class="str">iPhone</span>?"*** — Default `trailingCase: 'unchanged'` (`U_TITLECASE_NO_LOWERCASE`) never lowercases the tail — matching **93.5%** of GitHub call sites.
3. ***"Word segmentation is slow and fragile"*** — Single-span titlecasing needs **zero** segmentation (cf. Blink's 4.3% Speedometer regression, [crbug.com/420998400](https://crbug.com/420998400)).
4. ***"Editorial title-case stopwords are subjective"*** — They stay in userland:

```js
const segs = new Intl.Segmenter(locale, { granularity: 'word' });
let out = '';
for (const { segment, isWordLike } of segs.segment(str)) {
  out += isWordLike && !STOP.has(segment.toLocaleLowerCase(locale))
    ? segment.toLocaleCapitalize(locale, { trailingCase: 'lower' })
    : segment;
}
```
