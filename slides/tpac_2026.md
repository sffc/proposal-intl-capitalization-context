# Capitalization, Titlecasing, and Presentational Case Mapping

## Shane F. Carr (@sffc)
### W3C TPAC 2026 Breakout (#80) — CSSWG × W3C i18n × TC39-TG2

---

## Three Real-World Casing Disasters on the Web Today

1. **CSS `text-transform: capitalize` on Localized Dates & UI (`FullCalendar`, `immich` 70k⭐):**
   - Spanish date header: <span class="str">lunes, 12 de enero de 2026</span> $\to$ ❌ **<span class="str">Lunes, 12 De Enero De 2026</span>**
   - Russian calendar: <span class="str">сентябрь 2026 г.</span> $\to$ ❌ **<span class="str">Сентябрь 2026 Г.</span>**
   - Language picker: <span class="str">español de España</span> $\to$ ❌ **<span class="str">Español De España</span>**; <span class="str">srpski (latinica)</span> $\to$ ❌ **<span class="str">Srpski (Latinica)</span>**

2. **JS `str.charAt(0).toUpperCase() + str.slice(1)` on Non-ASCII Scripts (100k+ GitHub files):**
   - **Georgian (`ka`):** <span class="str">თბილისი</span> (*Tbilisi*) $\to$ ❌ **<span class="str">Თბილისი</span>** *(glues an ALL-CAPS Mtavruli capital onto lowercase Mkhedruli — Georgian does not capitalize words!)*
   - **Dutch (`nl`):** <span class="str">ijsland</span> (*Iceland*) $\to$ ❌ **<span class="str">Ijsland</span>** *(misses the <span class="str">IJ</span> digraph even with `toLocaleUpperCase('nl')`)*
   - **Adlam / Non-BMP DOM split:** `<span>{str[0].toUpperCase()}</span>{str.slice(1)}` $\to$ ❌ **<span class="str">𞤢𞤲𞤣</span>** *(tears UTF-16 surrogate pair into `U+FFFD U+FFFD`)*

3. **JS RegExp `\b\w` & CSS Screen Reader Leaks (`Angular #23267`, `w3c/accname#239`):**
   - `str.replace(/\b\w/g, c => c.toUpperCase())`: <span class="str">février</span> $\to$ ❌ **<span class="str">FéVrier</span>**; <span class="str">éclair</span> $\to$ ❌ **<span class="str">éClair</span>**; <span class="str">don't</span> $\to$ ❌ **<span class="str">Don'T</span>** (`\b\w` is ASCII-only!)
   - `<button style="text-transform: uppercase">Call us</button>` $\to$ Screen readers announce ❌ **<span class="str">Call U.S.</span>**

---

## Untangling Terminology

Standards discussions often stall because **"capitalize"** and **"titlecase"** refer to one of several distinct operations:

| Term | Precise Meaning | Examples |
| :--- | :--- | :--- |
| **Character Titlecase Mapping** | Maps a single letter/digraph according to Unicode titlecase rules (`Lt`) | <span class="str">ǆ</span> $\to$ <span class="str">ǅ</span>, <span class="str">ﬁ</span> $\to$ <span class="str">Fi</span><br/>Dutch <span class="str">ij</span> $\to$ <span class="str">IJ</span>, Georgian <span class="str">ა</span> $\to$ <span class="str">ა</span> (no-op) |
| **First-Letter Uppercase** | A broken, naive method (`s[0].toUpperCase() + s.slice(1)`) that many developers use to implement titlecasing | <span class="str">ijsland</span> $\to$ ❌ <span class="str">Ijsland</span><br/><span class="str">თბილისი</span> $\to$ ❌ <span class="str">Თბილისი</span> |
| **First-Word Titlecase** | Apply titlecase mapping to the first \~letter of a string (`titlecase-firstword`, trailing case unchanged) | <span class="str">español de España</span> $\to$ <span class="str">Español de España</span><br/><span class="str">«bonjour»</span> $\to$ <span class="str">«Bonjour»</span> |
| **Sentence Case** | Same as First-Word Titlecase but applied to every sentence in a string | <span class="str">hello world. ¡hola mundo!</span> $\to$ <span class="str">Hello world. ¡Hola mundo!</span> |
| **Every-Word Titlecase** | Apply titlecase mapping to the first \~letter of every \~word in a string (CSS `capitalize`) | <span class="str">español de España</span> $\to$ <span class="str">Español De España</span><br/><span class="str">out-of-the-box</span> $\to$ <span class="str">Out-Of-The-Box</span> |
| **Editorial Title Case** | Same as Every-Word Titlecase but with style guide rules (AP / Chicago / APA) to skip stopwords (<span class="str">of</span>, <span class="str">the</span>, <span class="str">de</span>) | <span class="str">the war of the worlds</span> $\to$ <span class="str">The War of the Worlds</span> |
| **Contextual Capitalization** | Based on a _UI context_ and _category_, choose the correct casing algorithm (`<contextTransforms>`) | <span class="str">septembre</span> (`fr` month) $\to$ <span class="str">Septembre</span> in calendar header, <span class="str">septembre</span> in menu |

---

## State in the Web Platform

<div class="columns">
<div>

### 1. CSS & HTML
- **`text-transform: capitalize;`**
  - Applies *Every-Word Titlecase* (`U_TITLECASE_NO_LOWERCASE`) to all text.
  - *Stopwords (`CSS Text 3 §2.1`):* Word boundaries are UA-dependent (`UAX #29` suggested); spec notes *"Authors cannot depend on `capitalize` to follow language-specific titlecasing conventions (such as skipping articles in English)"* — **no engine skips stopwords**.
- **`::first-letter`:** Block containers only (ignored on inline `<span>`, `<a>`).
- **HTML:** `autocapitalize` only hints mobile virtual keyboards; `<html lang>` is used by CSS **but ignored by JS `toLocaleUpperCase()`**.
- **Open CSS Issues:**
  - [w3c/csswg-drafts#8893](https://github.com/w3c/csswg-drafts/issues/8893) — First-Word / Sentence Case
  - [w3c/csswg-drafts#12526](https://github.com/w3c/csswg-drafts/issues/12526) — Editorial Title Case

</div>
<div>

### 2. JavaScript (`String` & `Intl`)
- **No native support** for titlecase mapping (`toUpperCase()` / `toLowerCase()` only).
- **`Intl` formatters** return a single default casing with **no UI context option**.
- **What developers do instead:**
  - **100,000+ GitHub files** (and **12,750+ `google3` files**) hardcode naive first-letter uppercase ([SO #1026069](https://stackoverflow.com/questions/1026069), **4.7M+ views**, baked into TypeScript `Capitalize<S>`, Vue, MUI, Angular, Closure).
  - **1.7M+ CSS/TSX/Vue files** apply `text-transform: capitalize`.
- **Open JS / `Intl` Issues:**
  - [tc39/ecma402#294](https://github.com/tc39/ecma402/issues/294) — Titlecase / Case Mapping in JS
  - [tc39/ecma402#355](https://github.com/tc39/ecma402/issues/355) — Contextual Capitalization in `Intl`

</div>
</div>

# Part 1: Bugs & Gaps in Applying Titlecase
## Why Naive JS & CSS Workarounds Fail Across Scripts

---

## Why Titlecase $\neq$ First-Letter Uppercase

<div class="columns">
<div>

### How Developers Do It Wrong Today
- **In JavaScript (`100k+` GitHub files):**
  ```js
  // Slices UTF-16 code unit 0 and uppercases it:
  const capitalize = s =>
    s.charAt(0).toUpperCase() + s.slice(1);
  ```
- **In CSS (`::first-letter` hack):**
  ```css
  /* Ignored on inline <span>/<a> without inline-block! */
  .label { display: inline-block; }
  .label::first-letter {
    text-transform: uppercase;
  }
  ```

</div>
<div>

### What True Titlecase Mapping Actually Requires
1. **Leading Adjustment (`Auto`):** Advance past <span class="str">«</span>, <span class="str">¿</span>, quotes, and Bidi isolates (`U+2068`); keep <span class="str">49ers</span> & Dutch <span class="str">'s-Gravenhage</span> intact.
2. **Unicode `Titlecase_Mapping` ($\neq$ `Uppercase`):** Code-point & grapheme awareness (surrogates, NFD combining marks), digraphs (<span class="str">ǆ</span> $\to$ <span class="str">ǅ</span>), ligatures (<span class="str">ﬁ</span> $\to$ <span class="str">Fi</span>), and **Georgian `ka` identity (no-op!)**.
3. **Locale Tailorings:** Dutch <span class="str">ij</span> $\to$ <span class="str">IJ</span>, Turkish <span class="str">i</span> $\to$ <span class="str">İ</span>, Greek initial *tonos* retention (<span class="str">άνθρωπος</span> $\to$ <span class="str">Άνθρωπος</span>, whereas `uppercase` strips accents $\to$ <span class="str">ΑΝΘΡΩΠΟΣ</span>), Lithuanian dot removal, Irish `ga` prefixes.
4. **Trailing Case (`Unchanged`):** Preserve <span class="str">MacDonald</span>, <span class="str">iPhone</span>, <span class="str">España</span>, <span class="str">COVID-19</span>.

</div>
</div>

---

## Character & Script Failures: `str[0].toUpperCase()` Is Not Titlecase

`str[0].toUpperCase() + str.slice(1)` applies **`Uppercase_Mapping` to UTF-16 code unit 0** instead of **`Titlecase_Mapping` to the first word**:

| Script / Rule | Input | `str[0].toUpperCase() + str.slice(1)` | Correct Titlecase | Why It Fails (Verified Live in V8) |
| :--- | :--- | :--- | :--- | :--- |
| **Georgian (`ka`)** | <span class="str">თბილისი</span> (*Tbilisi*)<br><span class="str">იანვარი</span> (*January*) | ❌ **<span class="str">Თბილისი</span>**<br>❌ **<span class="str">Იანვარი</span>** | **<span class="str">თბილისი</span>**<br>**<span class="str">იანვარი</span>** | Georgian has no word capitalization (`Titlecase_Mapping` = self; *Mtavruli* <span class="str">Თ</span> is strictly ALL-CAPS!) |
| **Dutch <span class="str">ij</span> (`nl`)** | <span class="str">ijsland</span> (*Iceland*) | ❌ **<span class="str">Ijsland</span>** *(even with `toLocaleUpperCase('nl')`!)* | **<span class="str">IJsland</span>** | `str[0]` only passes <span class="str">i</span>, hiding the <span class="str">ij</span> digraph from the case mapper |
| **Serbo-Croatian (`Lt`)** | <span class="str">ǆep</span> (*pocket*) | ❌ **<span class="str">Ǆep</span>** (<span class="str">DŽep</span>) | **<span class="str">ǅep</span>** (<span class="str">Džep</span>) | `U+01C6` maps to `Lt` <span class="str">ǅ</span> (`U+01C5`), not `Lu` <span class="str">Ǆ</span> (`U+01C4`) |
| **Ligatures & Armenian** | <span class="str">ﬁrst</span>, <span class="str">ևս</span> | ❌ **<span class="str">FIrst</span>**, **<span class="str">ԵՒս</span>** | **<span class="str">First</span>**, **<span class="str">Եւս</span>** | `SpecialCasing.txt` upper (<span class="str">FI</span>, <span class="str">ԵՒ</span>) $\neq$ title (<span class="str">Fi</span>, <span class="str">Եւ</span>) |
| **Greek Polytonic (`Lt`)** | <span class="str">ᾳδης</span> (*Hades*) | ❌ **<span class="str">ΑΙδης</span>** | **<span class="str">ᾼδης</span>** | Upper expands *ypogegrammeni* to two capitals (<span class="str">ΑΙ</span>); title uses *prosgegrammeni* (<span class="str">ᾼ</span>) |
| **Turkish (`tr` / `az`)** | <span class="str">istanbul</span> | ❌ **<span class="str">Istanbul</span>** | **<span class="str">İstanbul</span>** | `.toUpperCase()` is locale-blind, and `.toLocaleUpperCase()` ignores `<html lang="tr">`! |

## Surrogates, Leading Punctuation, `\b\w`, & Trailing Case

<div class="columns">
<div>

### 1. Surrogates, Combining Marks, & Leading Punctuation
- **UTF-16 Surrogates (9 bicameral scripts):** In **Adlam** (<span class="str">𞤢𞤤𞤢𞤲𞤣</span> *Sunday*), **Deseret**, **Osage**, `str[0]` is a lone high surrogate (`\uD83A`) — `.toUpperCase()` is a **silent no-op** (`camelcase#117`), and `<span>{str[0]}</span>{str.slice(1)}` renders `U+FFFD`!
- **Lithuanian (`lt`) & NFD:** Slicing `str[0]` on `"i\u0307\u0303"` hides `\u0307`, leaving a double-dotted **<span class="str">İ̃</span>** (`"I\u0307\u0303"`).
- **Leading Punctuation & Elisions:** <span class="str">¿cómo estás?</span>, <span class="str">«bonjour»</span>, and **Fluent** Bidi isolates (`"\u2068lundi\u2069"`) fail at `str[0]`; naive `ToCased` corrupts <span class="str">49ers</span> $\to$ **<span class="str">49Ers</span>** and Dutch <span class="str">'s-Gravenhage</span> $\to$ **<span class="str">'S-Gravenhage</span>**.

</div>
<div>

### 2. RegExp `\b\w` & `.slice(1).toLowerCase()` Bugs
- **ASCII-Only RegExp (`str.replace(/\b\w/g, ...)`):**
  - `\b` and `\w` are **strictly ASCII** (`Angular #23267`):
  - <span class="str">éclair</span> $\to$ ❌ **<span class="str">éClair</span>**; <span class="str">février</span> $\to$ ❌ **<span class="str">FéVrier</span>**
  - <span class="str">FOGÃO</span> $\to$ ❌ **<span class="str">FogãO</span>**; <span class="str">don't</span> $\to$ ❌ **<span class="str">Don'T</span>**
- **Why `.slice(1).toLowerCase()` & Name Normalization Fail:**
  - Destroys <span class="str">Español de España</span> $\to$ **<span class="str">Español de españa</span>**, <span class="str">COVID-19</span> $\to$ **<span class="str">Covid-19</span>** (`angular#41420`), <span class="str">iPhone</span> $\to$ **<span class="str">Iphone</span>**.
  - Corrupts person names (<span class="str">maría josé</span> $\to$ <span class="str">María josé</span>, <span class="str">McDonald</span> $\to$ <span class="str">Mcdonald</span>, <span class="str">van der Berg</span> $\to$ <span class="str">Van Der Berg</span>).

</div>
</div>

## CSS Gaps: Every-Word Over-Casing, `::first-letter`, & Leaks

<div class="columns">
<div>

### 1. `text-transform: capitalize` Forces Every-Word Casing
In 1,000 CSS/Vue/TSX fragments studied, `.capitalize` is applied to translated headings, weather, dates, and language pickers:
```html
<h2 class="text-capitalize">{{ $t('our_services') }}</h2>
<span class="capitalize">{{ weather.description }}</span>
<p class="capitalize">{{ date.toLocaleDateString('es') }}</p>
```
- **French heading:** <span class="str">nos services numériques</span> $\to$ ❌ **<span class="str">Nos Services Numériques</span>** *(wants <span class="str">Nos services numériques</span>)*
- **Spanish/French weather (1,908 files):** <span class="str">cielo claro</span> $\to$ ❌ **<span class="str">Cielo Claro</span>**; <span class="str">ciel dégagé</span> $\to$ ❌ **<span class="str">Ciel Dégagé</span>**
- **Language pickers (`immich`):** <span class="str">español de España</span> $\to$ ❌ **<span class="str">Español De España</span>**; <span class="str">norsk bokmål</span> $\to$ ❌ **<span class="str">Norsk Bokmål</span>**

</div>
<div>

### 2. Why `::first-letter` Fails & CSS Leaks
- **Why `.label::first-letter` doesn't save us:**
  - **Ignored on inline elements (`<span>`, `<a>`, `<label>`)** (`CSS Pseudo-Elements 4 §2.2`).
  - `::first-letter { text-transform: uppercase }` strips Greek initial *tonos* (<span class="str">Άνθρωπος</span> $\to$ ❌ **<span class="str">Ανθρωπος</span>**) and applies Georgian Mtavruli (<span class="str">Თბილისი</span>).
  - Even `::first-letter { text-transform: capitalize }` fails in Blink on Dutch <span class="str">ijsland</span> $\to$ **<span class="str">Ijsland</span>** (`crbug.com/1172333`) and `"«\u00A0bonjour"` (`crbug.com/41270370`).
- **Accessibility, Clipboard, & Non-CSS Sinks:**
  - **Screen readers (`w3c/accname#239`):** `<button style="text-transform: uppercase">Call us</button>` $\to$ announced as **<span class="str">Call U.S.</span>**
  - **Clipboard & `innerText` (`webkit.org/b/43202`):** Mutates copied text.
  - **Cannot reach:** `<title>`, `<option>`, `aria-label`, `<canvas>`, `Notification`.

</div>
</div>

# Part 2: Contextual Capitalization
## Even With a Good Titlecase Algorithm, *When* Should You Apply It?

---

## Capitalization According to CLDR and Unicode

<div class="columns">
<div>

### Phase 1: Contextual Decision

**Input:** Locale, UI Context, Lexical Category
**Output:** Algorithm Choice *(via CLDR `<contextTransforms>`)*

_Example UI Contexts (`UTS #35` + UI):_
- **Middle of sentence** (`middle-of-sentence` — CLDR default)
- **Beginning of sentence** (`beginning-of-sentence`)
- **Menu / list item** (`uiListOrMenu`)
- **Standalone label / header** (`stand-alone`)
- **Headline / Title** (Editorial UI chrome)

_Example Lexical Categories:_
- **CLDR nouns:** Month/day name, Language/region name, Relative date (<span class="str">yesterday</span>), Currency/unit
- **Person name** (Always `no-change`)
- **Prose / UI label**

</div>
<div>

### Phase 2: Case Map Execution

**Input:** Locale, String, Algorithm Choice
**Output:** Case-Mapped String *(Part 1!)*

_Algorithm Choices:_
- **`no-change`:** Leave string as-is *(mid-sentence, Swedish standalone months, French menu months, person names)*
- **`First-Word Titlecase` (`titlecase-firstword`):** `ICU4X TitlecaseMapper::titlecase_segment` / `ICU4C U_TITLECASE_WHOLE_STRING` with `TrailingCase::Unchanged` & `LeadingAdjustment::Auto` *(zero `BreakIterator` cost!)*
- **`Sentence Case`:** First-Word Titlecase per `UAX #29` sentence
- **`Every-Word Titlecase`:** Titlecase per `UAX #29` word (CSS `capitalize`)
- **`Editorial Title Case`:** Every-Word Titlecase skipping stopwords (<span class="str">of</span>, <span class="str">the</span>, <span class="str">de</span>)

</div>
</div>

---

## Why Unconditional First-Word Casing Fails (`<contextTransforms>`)

Developers who notice CSS `capitalize` hits every word switch to JS (as Spanish devs noted in comments: *"Con `capitalize` de CSS quedaba <span class="str">Septiembre De 2026</span>"*) and hardcode **First-Word Casing for every locale and UI slot**:

```js
// Found across dozens of GitHub calendar, datepicker, and i18n utilities:
function formatMonthLabel(date, locale) {
  const s = date.toLocaleDateString(locale, { month: 'long', year: 'numeric' });
  return capitalizeFirstWord(s, locale); // ❌ Runs for EVERY locale & UI context!
}
```

**Why neither CSS (`text-transform: first-word`) nor unconditional JS can make the Phase 1 decision for `Intl` data:**

| Item & UI Context | Spanish (`es`) | French (`fr`) | Czech (`cs`) | Swedish (`sv`) / Finnish (`fi`) |
| :--- | :---: | :---: | :---: | :---: |
| **Month in Calendar Header (`stand-alone`)** | <span class="str">Septiembre</span> (Cap) | <span class="str">Septembre</span> (Cap) | **<span class="str">září</span> (`no-change`)** | **<span class="str">september</span> / <span class="str">syyskuu</span> (`no-change`)** |
| **Month in `<select>` Menu (`uiListOrMenu`)** | <span class="str">Septiembre</span> (Cap) | **<span class="str">septembre</span> (`no-change`)** | <span class="str">Září</span> (Cap) | **<span class="str">september</span> / <span class="str">syyskuu</span> (`no-change`)** |
| **Language in `<select>` Menu (`uiListOrMenu`)** | <span class="str">Español</span> (Cap) | <span class="str">Français</span> (Cap) | <span class="str">Čeština</span> (Cap) | <span class="str">Svenska</span> / <span class="str">Suomi</span> (Cap) |
| **Language Standalone (`stand-alone`)** | <span class="str">Español</span> (Cap) | **<span class="str">français</span> (`no-change`)** | <span class="str">Čeština</span> (Cap) | <span class="str">Svenska</span> / **<span class="str">suomi</span> (`no-change`)** |
| **In Running Text (`middle-of-sentence`)** | **<span class="str">septiembre</span>** | **<span class="str">septembre</span>** | **<span class="str">září</span>** | **<span class="str">september</span> / <span class="str">syyskuu</span>** |

## How `Intl` Leaves Browsers & Locales Inconsistent Today

CLDR stores terms in **middle-of-sentence** form (<span class="str">enero</span>, <span class="str">janvier</span>, <span class="str">español</span>, <span class="str">русский</span>) and uses `<contextTransforms>` (compiled in ICU to a tiny 2-bit flag vector per category) for UI contexts. Because `ECMA-402` has not exposed context (`ecma402#355`):

<div class="columns">
<div>

### 1. Cross-Browser Divergence in `Intl.DisplayNames`
- **V8 (Chrome):** passes `UDISPCTX_CAPITALIZATION_NONE`
- **SpiderMonkey (Firefox) & JSC (Safari):** pass `UDISPCTX_CAPITALIZATION_FOR_STANDALONE`

```js
new Intl.DisplayNames(['es'], { type: 'language' })
  .of('es');
// Chrome:         "español" (lowercase)
// Firefox/Safari: "Español" (Capitalized)

new Intl.DisplayNames(['fr'], { type: 'language' })
  .of('fr');
// ALL browsers:   "français" (lowercase!)
// Why? CLDR 'fr' (and 'fi', 'da') only capitalizes
// languages in uiListOrMenu, not stand-alone!
```

</div>
<div>

### 2. Real-World Pain in Production UIs
- **Perplexity Language Picker (`ecma402#355`):**
  Across ~50 interface languages in Chrome, `Intl.DisplayNames` returns **27 lowercase** (<span class="str">español</span>, <span class="str">français</span>, <span class="str">русский</span>, <span class="str">polski</span>, <span class="str">čeština</span>, <span class="str">suomi</span>) and **~23 capitalized** (<span class="str">English</span>, <span class="str">Deutsch</span>, <span class="str">Nederlands</span>, <span class="str">Türkçe</span>).
- **Project Fluent (`fluent#299`) & FormatJS (`#1527`):**
  Maintainers declined to add custom casing filters, pointing to `ecma402#355` as the missing platform primitive.

## What Are Developers Actually Capitalizing? (GitHub Study)

Across **563 classified JS hits** (400 real call sites) + **~190 localized `Intl` call sites** + **1,000 CSS `.capitalize` fragments** + **2,000+ multilingual human-text lines**:

| :--- | :---: | :--- |
| **Internal keys/enums/statuses $\to$ UI labels, chips, tabs, headers, & translated strings (`$t('files')`)** | **51% of JS hits**<br>*(+ 33% of Vue `$t()` `.capitalize`)* | **Phase 2 (`titlecase-firstword`):** CSS `text-transform: first-word` (`#8893`) or JS (`#294`, `trailingCase: 'unchanged'`) |
| **API/DB phrases (`weather[0].description`), Go/Rust `error.message` toasts, transcripts, MF2** | **14.5% of JS hits**<br>*(1,908 weather + 106 error files; 0% lower tail!)* | **Phase 2 in JS (`#294`):** Single-span capitalization with `leadingAdjustment: 'auto'` & `trailingCase: 'unchanged'` |
| **`Intl` / date-library outputs (`DateTimeFormat`, `DisplayNames`, `RelativeTimeFormat`)** | **~1% random JS**<br>*(~10–15% TS file ceiling + ~25–30% of CSS date/calendar hits)* | **Phase 1 + 2 in `Intl` (`#355`):** CLDR `<contextTransforms>` (`standalone`, `ui-list-or-menu`, `beginning-of-sentence`) + **CLDR data audit** |
| **Person & place names (`nombre`, `prenom`, `isim`)** | **6.5% of JS hits**<br>*(only group using `.toLowerCase()`!)* | **`no-change`:** Do not case-normalize names; use UTS #35 Part 8 `initialPattern` (`Intl.PersonNames`) for initials |
| **Code / identifier generation (`PascalCase`, `on${Key}`)** | **26% of JS hits** | ASCII `s[0].toUpperCase() + s.slice(1)` *(locale-insensitive, already works)* |

> **Key Takeaway:** Neither `Intl` (`#355`), nor CSS (`#8893`), nor a JS primitive (`#294`) can solve this alone—each covers a distinct slice of the Web, and all three share the **same Phase 2 execution**.

## Solution Track 1: CSS (`css-text`) & Accessibility Alignment (Phase 2)

<div class="columns">
<div>

### 1. Standardize `text-transform: first-word` / `sentence` (`csswg-drafts#8893`)
- Direct declarative primitive for **First-Word Titlecase** (`titlecase-firstword`):
  - Applies Unicode `Titlecase_Mapping` + `TrailingCase::Unchanged` + `LeadingAdjustment::Auto` to the first word of an element.
  - **Works on inline elements (`<span>`, `<a>`, `<label>`)** as well as blocks — eliminating `display: inline-block` `::first-letter` hacks and Greek *tonos* / Georgian *Mtavruli* bugs.
  - Replaces `.capitalize` on UI headings, chips, badges, and translated strings (<span class="str">Nos services numériques</span>).
- *What about Editorial Title Case (`#12526`)?* Stop words (<span class="str">of</span>, <span class="str">the</span>) are style-guide-specific (AP vs. Chicago); leave to userland or custom `@text-transform` (`#3132`).

</div>
<div>

### 2. Fix Tailoring Interop, Perf, & Leaks
- **Shared segment fast-path:** Avoid Blink's 4.3% Speedometer 3 regression (`crbug.com/420998400` when shipping Dutch <span class="str">IJ</span> in `crbug.com/41248541`) by caching `BreakIterator` for `capitalize` and using zero-breaker segment titlecasing (`ICU4X titlecase_segment` / `ICU4C U_TITLECASE_WHOLE_STRING`) for `first-word`.
- **Language tailorings & word boundaries:** Align engines on Dutch <span class="str">IJ</span>, Irish `ga` prefix mutations (<span class="str">an t-uisce</span> $\to$ <span class="str">AN tUISCE</span>, currently Gecko-only), and UAX #29 word boundaries (<span class="str">foo.bar</span>, <span class="str">cancel·lar</span>).
- **Fix Accessibility & Clipboard Leaks:** Do not expose visual `text-transform` mutations to `accname` (`w3c/accname#239`) or Safari plain-text clipboard (`webkit.org/b/43202`).

</div>
</div>

## Solution Track 2: Contextual Capitalization in `Intl` (`#355`) (Phase 1 + 2)

<div class="columns">
<div>

### 1. Expose `capitalization` Option in `Intl`
For CLDR nouns (`DateTimeFormat`, `DisplayNames`, `RelativeTimeFormat`), **only `Intl` knows the lexical category** needed for Phase 1:

```js
// Standalone calendar header:
new Intl.DateTimeFormat(locale, {
  month: 'long', year: 'numeric',
  capitalization: 'standalone',
  // 'middle-of-sentence' (default) | 'beginning-of-sentence'
  // | 'ui-list-or-menu' | 'standalone'
}).format(date);
// es -> "Septiembre de 2026"
// sv -> "september 2026" (respects Swedish no-change!)

// Language picker menu:
new Intl.DisplayNames([locale], {
  type: 'language',
  capitalization: 'ui-list-or-menu',
}).of('es-ES');
// fr -> "Espagnol d’Espagne" (vs "espagnol d’Espagne")
```
- Resolves Chrome vs. Firefox/Safari `Intl.DisplayNames` divergence by specifying `'middle-of-sentence'` as the default.

</div>
<div>

### 2. Co-Requisite: CLDR & ICU Data Audit
Our GitHub call-site audit revealed missing CLDR `<contextTransforms>` flags where native speakers expect capitalization:
1. **Portuguese (`pt`) months:** #1 locale in our GitHub study (27 `pt-BR` sites capitalizing <span class="str">Setembro de 2026</span>), yet `pt.xml` has `days` and `relative` **but is missing `month-*`**!
2. **Language pickers (`languages`):** Missing `uiListOrMenu` in **`pl` (<span class="str">polski</span>), `hu` (<span class="str">magyar</span>), `ca` (<span class="str">català</span>), `ro` (<span class="str">română</span>), `bg` (<span class="str">български</span>), `sr`, `sl`, `lt`, `lv`, `et`, `is`** (half of Perplexity's 27 lowercase languages!).
3. **Relative dates (`relative`):** Missing in **`fr` (<span class="str">hier</span>), `es` (<span class="str">ayer</span>), `it` (<span class="str">ieri</span>)**; and ICU4C `RelativeDateTimeFormatter` (`reldatefmt.cpp:816`) currently ignores `STANDALONE` & `UI_LIST_OR_MENU`!

</div>
</div>

## Solution Track 3: JS Case Mapping Building Block (`#294`) (Phase 2)

How do we fix the **90%+ of JS call sites** that transform non-`Intl` strings (weather/API text, error toasts, `<title>`, `<option>`, `aria-label`, MF2 messages) while addressing all TG2 vendor objections?

<div class="columns">
<div>

### Single-Span Primitive + `Intl.Segmenter`
```js
// 1. Direct replacement for s[0].toUpperCase() + s.slice(1)
// (Default: trailingCase: 'unchanged', leadingAdjustment: 'auto')
str.toLocaleCapitalize(locale);
// "cielo claro" ('es')     -> "Cielo claro"
// "«bonjour»" ('fr')       -> "«Bonjour»"
// "\u2068lundi\u2069"      -> "\u2068Lundi\u2069"
// "ijsland" ('nl')         -> "IJsland"
// "'s-Gravenhage" ('nl')   -> "'s-Gravenhage"
// "თბილისი" ('ka')         -> "თბილისი" (no-op!)
// "ǆep" ('hr')             -> "ǅep"

// 2. Composes with Intl.Segmenter for 1KB userland Title Case:
const segs = new Intl.Segmenter(locale, { granularity: 'word' });
let out = '';
for (const { segment, isWordLike } of segs.segment(str)) {
  out += isWordLike && !STOP.has(segment.toLocaleLowerCase(locale))
    ? segment.toLocaleCapitalize(locale, { trailingCase: 'lower' })
    : segment;
}
```

</div>
<div>

### Resolves All 4 TG2 Vendor Objections
1. **Why not CSS-only?** Non-CSS sinks (`<title>`, `<option>`, `aria-label`, `<canvas>`, `Notification`), MF2 functions (`message-format-wg#38`), and avoiding `accname`/clipboard leaks.
2. **<span class="str">MacDonald</span> & <span class="str">iPhone</span> preserved:** Default `trailingCase: 'unchanged'` never lowercases <span class="str">MacDonald</span>, <span class="str">iPhone</span>, <span class="str">COVID-19</span>, or <span class="str">España</span>.
3. **Zero `BreakIterator` regression:** Single-span default (`U_TITLECASE_WHOLE_STRING` / `ICU4X titlecase_segment`) requires **no word segmenter**, avoiding Blink's 4.3% Speedometer 3 regression.
4. **Stop words stay in userland:** Style-guide rules (AP vs. Chicago) don't bloat browser engines; method name avoids the overloaded term `"titleCase"`.

</div>
</div>

## Summary: Matching Each Use Case to the Right Tool

| Real-World Use Case (from GitHub Study) | Broken Code Today | Proposed Platform Solution |
| :--- | :--- | :--- |
| **Declarative UI headings, chips, badges, inline `<span>`s, translated labels** (`$t('...')`, status labels) | `text-transform: capitalize` (forces every-word casing onto `fr`/`es`/`no`) or block-only `::first-letter` | **CSS `text-transform: first-word` / `sentence` (`#8893`)** + engine tailoring & `accname` fixes |
| **`Intl` dates, months, weekdays, languages, relative time in headers & menus** | `cap(date.toLocaleDateString(...))` or CSS `.capitalize` (ignores `sv`/`fr`/`cs` `no-change` rules) | **`Intl` `{ capitalization: 'standalone' \| 'ui-list-or-menu' \| ... }` (`ecma402#355`)** + CLDR `<contextTransforms>` audit |
| **Non-`Intl` strings in JS: toasts, API phrases (`weather.description`), MF2, `<title>`, `<option>`, `aria-label`** | `s.charAt(0).toUpperCase() + s.slice(1)` (breaks `ka`, `nl` <span class="str">IJ</span>/<span class="str">'s-</span>, `tr` <span class="str">İ</span>, `Lt` digraphs, surrogates, <span class="str">«</span>/<span class="str">¿</span>, `U+2068`) | **JS First-Word / Segment Capitalization Primitive (`ecma402#294`)** (`trailingCase: 'unchanged'` default) |

| **Person names & initials** (`nombre`, `prenom`, `isim`) | `name.split(' ').map(w => w[0].toUpperCase() + w.slice(1).toLowerCase())` | **Do not case-normalize names (`no-change`)**; use **UTS #35 Part 8 (`initialPattern`)** for initials |
