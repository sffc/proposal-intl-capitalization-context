# Capitalization, Titlecasing, and Presentational Case Mapping

## Shane F. Carr (@sffc)
### W3C TPAC 2026 Breakout ([#80](https://github.com/w3c/tpac2026-breakouts/issues/80)) — CSSWG × W3C i18n × TC39-TG2

---

## Three Real-World Casing Disasters on the Web Today

1. **CSS `text-transform: capitalize` on Localized Dates & UI (`FullCalendar`, `immich` 70k⭐):**
   - Spanish date header: <span class="str">lunes, 12 de enero de 2026</span> $\to$ ❌ **<span class="str">Lunes, 12 De Enero De 2026</span>**
   - Russian calendar: <span class="str">сентябрь 2026 г.</span> $\to$ ❌ **<span class="str">Сентябрь 2026 Г.</span>**
   - Language picker: <span class="str">español de España</span> $\to$ ❌ **<span class="str">Español De España</span>**; <span class="str">srpski (latinica)</span> $\to$ ❌ **<span class="str">Srpski (Latinica)</span>**

2. **JS `str.charAt(0).toUpperCase() + str.slice(1)` on Non-ASCII Scripts (100k+ GitHub files):**
   - **Georgian (`ka`):** <span class="str">თბილისი</span> (*Tbilisi*) $\to$ ❌ **<span class="str">Თბილისი</span>** *(glues an ALL-CAPS Mtavruli capital onto lowercase Mkhedruli — Georgian does not capitalize words!)*
   - **Dutch (`nl`):** <span class="str">ijsland</span> (*Iceland*) $\to$ ❌ **<span class="str">Ijsland</span>** *(misses the <span class="str">IJ</span> digraph even with `toLocaleUpperCase('nl')`)*
   - **Adlam / Non-BMP DOM split:** `<span>{str[0].toUpperCase()}</span>{str.slice(1)}` $\to$ ❌ **<span class="str">𞤢𞤲𞤣</span>** *(tears UTF-16 surrogate pair into `U+FFFD U+FFFD`)*

3. **JS RegExp `\b\w` & CSS Screen Reader Leaks ([angular/angular#23267](https://github.com/angular/angular/issues/23267), [w3c/accname#239](https://github.com/w3c/accname/issues/239)):**
   - `str.replace(/\b\w/g, c => c.toUpperCase())`: <span class="str">février</span> $\to$ ❌ **<span class="str">FéVrier</span>**; <span class="str">éclair</span> $\to$ ❌ **<span class="str">éClair</span>**; <span class="str">don't</span> $\to$ ❌ **<span class="str">Don'T</span>** (`\b\w` is ASCII-only!)
   - `<button style="text-transform: uppercase">Call us</button>` $\to$ Screen readers announce ❌ **<span class="str">Call U.S.</span>**

## Untangling Terminology

Standards discussions often stall because **"capitalize"** and **"titlecase"** refer to one of several distinct operations:

| Term | Precise Meaning | Examples |
| :--- | :--- | :--- |
| **Character Titlecase Mapping** | Maps a single letter/digraph according to Unicode titlecase rules (`Lt`) | <span class="str">ǆ</span> $\to$ <span class="str">ǅ</span>, <span class="str">ﬁ</span> $\to$ <span class="str">Fi</span><br/>Dutch <span class="str">ij</span> $\to$ <span class="str">IJ</span>, Georgian <span class="str">ა</span> $\to$ <span class="str">ა</span> (no-op) |
| **First-Word Titlecase** | Apply titlecase mapping to the first \~letter of a string (`titlecase-firstword`, trailing case unchanged) | <span class="str">español de España</span> $\to$ <span class="str">Español de España</span><br/><span class="str">«bonjour»</span> $\to$ <span class="str">«Bonjour»</span> |
| **Sentence Case** | Same as First-Word Titlecase but applied to every sentence in a string | <span class="str">hello world. ¡hola mundo!</span> $\to$ <span class="str">Hello world. ¡Hola mundo!</span> |
| **Every-Word Titlecase** | Apply titlecase mapping to the first \~letter of every \~word in a string (CSS `capitalize`) | <span class="str">español de España</span> $\to$ <span class="str">Español De España</span><br/><span class="str">out-of-the-box</span> $\to$ <span class="str">Out-Of-The-Box</span> |
| **Editorial Title Case** | Same as Every-Word Titlecase but with style guide rules (AP / Chicago / APA) to skip stopwords (<span class="str">of</span>, <span class="str">the</span>, <span class="str">de</span>) | <span class="str">the war of the worlds</span> $\to$ <span class="str">The War of the Worlds</span> |
| **Contextual Capitalization** | Based on a _UI context_ and _category_, choose the correct casing algorithm (`<contextTransforms>`) | <span class="str">septembre</span> (`fr` month) $\to$ <span class="str">Septembre</span> in calendar header, <span class="str">septembre</span> in menu |

---

## State in the Web Platform

<div class="columns">
<div>

### 1. CSS & HTML
- **`text-transform: capitalize;`**
  - Applies *Every-Word Titlecase* (`U_TITLECASE_NO_LOWERCASE`) to all text.
  - *Stopwords (`CSS Text 3 §2.1`):* Word boundaries are UA-dependent (`UAX #29` suggested); spec notes *"Authors cannot depend on `capitalize` to follow language-specific titlecasing conventions (such as skipping articles in English)"* — **no engine skips stopwords**.
- **`::first-letter`:** Block containers only (ignored on inline `<span>`, `<a>`).
- **HTML:** `autocapitalize` only hints mobile virtual keyboards; `<html lang>` is used by CSS **but ignored by JS `toLocaleUpperCase()`**.
- **Open CSS Issues:**
  - [w3c/csswg-drafts#8893](https://github.com/w3c/csswg-drafts/issues/8893) — First-Word / Sentence Case
  - [w3c/csswg-drafts#12526](https://github.com/w3c/csswg-drafts/issues/12526) — Editorial Title Case

</div>
<div>

### 2. JavaScript (`String` & `Intl`)
- **No native support** for titlecase mapping (`toUpperCase()` / `toLowerCase()` only).
- **`Intl` formatters** return a single default casing with **no UI context option**.
- **What developers do instead:**
  - **100,000+ GitHub files** hardcode naive first-letter uppercase ([SO #1026069](https://stackoverflow.com/questions/1026069), **4.7M+ views**, baked into TypeScript `Capitalize<S>`, Vue, MUI, Angular).
  - **1.7M+ CSS/TSX/Vue files** apply `text-transform: capitalize`.
- **Open JS / `Intl` Issues:**
  - [tc39/ecma402#294](https://github.com/tc39/ecma402/issues/294) — Titlecase / Case Mapping in JS
  - [tc39/ecma402#355](https://github.com/tc39/ecma402/issues/355) — Contextual Capitalization in `Intl`

</div>
</div>

# Part 1: Bugs & Gaps in Applying Titlecase
## Why Naive JS & CSS Workarounds Fail Across Scripts

---

## Why Titlecase $\neq$ First-Letter Uppercase

What **True Titlecase Mapping** actually requires — and why uppercasing the first character fails:

1. **Unicode `Titlecase_Mapping` ($\neq$ `Uppercase_Mapping`):**
   - **Georgian (`ka`) is unicameral in mixed text (`Titlecase` = identity no-op):** <span class="str">თბილისი</span> (*Tbilisi*) $\to$ **<span class="str">თბილისი</span>**; `str[0].toUpperCase()` produces ❌ **<span class="str">Თბილისი</span>** *(gluing an ALL-CAPS Mtavruli letter onto Mkhedruli!)*.
   - **Digraphs & Ligatures (`SpecialCasing.txt`):** Serbo-Croatian <span class="str">ǆep</span> $\to$ **<span class="str">ǅep</span>** (not `Lu` ❌ <span class="str">Ǆep</span>); ligature <span class="str">ﬁrst</span> $\to$ **<span class="str">First</span>** (not ❌ <span class="str">FIrst</span>); Armenian <span class="str">ևս</span> $\to$ **<span class="str">Եւս</span>** (not ❌ <span class="str">ԵՒս</span>); Greek polytonic <span class="str">ᾳδης</span> $\to$ **<span class="str">ᾼδης</span>** (not ❌ <span class="str">ΑΙδης</span>).
2. **Locale Tailorings Across Multi-Char Prefixes:**
   - **Dutch (`nl`) <span class="str">ij</span> digraph:** <span class="str">ijsland</span> (*Iceland*) $\to$ **<span class="str">IJsland</span>** (`str[0]` only passes <span class="str">i</span>, producing ❌ **<span class="str">Ijsland</span>** even with `toLocaleUpperCase('nl')`!).
   - **Turkish (`tr`/`az`) & Greek (`el`):** <span class="str">istanbul</span> $\to$ **<span class="str">İstanbul</span>** (not ❌ <span class="str">Istanbul</span>); Greek titlecase retains initial *tonos* (<span class="str">άνθρωπος</span> $\to$ **<span class="str">Άνθρωπος</span>**), whereas `uppercase` strips accents ($\to$ <span class="str">ΑΝΘΡΩΠΟΣ</span>).
3. **Leading Adjustment (`Auto`):** Advance past <span class="str">«bonjour»</span>, <span class="str">¿cómo?</span>, quotes, and Bidi isolates (`U+2068`); keep <span class="str">49ers</span> & Dutch <span class="str">'s-Gravenhage</span> intact.
4. **Trailing Case (`Unchanged`):** Preserve <span class="str">MacDonald</span>, <span class="str">iPhone</span>, <span class="str">España</span>, <span class="str">COVID-19</span>.

---

## The Ubiquity of Naive First-Letter Uppercase in JS

Because JavaScript lacks a titlecase primitive ([tc39/ecma402#294](https://github.com/tc39/ecma402/issues/294)), the entire ecosystem copies one broken snippet:

```js
const capitalize = (s) => s.charAt(0).toUpperCase() + s.slice(1);
```

- **100,000+ public GitHub source files** hardcode `charAt(0).toUpperCase() + slice(1)` (or `str[0].toUpperCase() + str.slice(1)`).
- **[Stack Overflow #1026069](https://stackoverflow.com/questions/1026069)** (*"How do I make the first letter of a string uppercase in JavaScript?"*) has **4.7M+ views** and 4,500+ upvotes recommending this exact function.
- **Baked into core language types & major UI frameworks:**
  - **TypeScript intrinsic `Capitalize<S>`:** Implemented inside the compiler as `s.charAt(0).toUpperCase() + s.slice(1)`.
  - **Vue (`@vue/shared`), MUI (`@mui/utils`), Angular, Lodash (`_.upperFirst`):** All ship this exact code-unit-0 uppercase helper.
- **Even i18n maintainers tell developers to write it:**
  - Issue trackers for **FormatJS ([#1527](https://github.com/formatjs/formatjs/issues/1527)), Moment.js, and `date-fns`** explicitly advise users to post-process formatted dates and strings with `s[0].toUpperCase() + s.slice(1)`.
- **Zero locale awareness:** In our 563-hit GitHub sample, **0 out of 563** call sites passed a locale to `toLocaleUpperCase(locale)`.

---

## JS Bugs (1): Surrogates, Combining Marks, & Leading Punctuation

1. **UTF-16 Surrogates (9 Bicameral Non-BMP Scripts):**
   - In **Adlam** (<span class="str">𞤢𞤤𞤢𞤲𞤣</span> *Sunday*), **Deseret**, **Osage**, and **Warang Citi**, `str[0]` is a lone high surrogate (`\uD83A`).
   - `str[0].toUpperCase()` is a **silent no-op** ([sindresorhus/camelcase#117](https://github.com/sindresorhus/camelcase/issues/117)).
   - Worse, JSX drop-cap splits (`<span>{str[0].toUpperCase()}</span>{str.slice(1)}`) tear the surrogate pair across DOM nodes into **`U+FFFD U+FFFD`** (❌ <span class="str">𞤤𞤢𞤲𞤣</span>)!

2. **Lithuanian (`lt`) & NFD Combining Marks:**
   - Slicing `str[0]` on NFD `"i\u0307\u0303"` separates the base `"i"` from its combining marks (`\u0307`), leaving a corrupted double-dotted ❌ **<span class="str">İ̃</span>** (`"I\u0307\u0303"`).

3. **Leading Punctuation, Bidi Isolates, & Elisions:**
   - <span class="str">¿cómo estás?</span> and <span class="str">«bonjour»</span> fail at `str[0]` because index `0` is punctuation.
   - **Project Fluent** wraps interpolated terms in Bidi isolates (`"\u2068lundi\u2069"`) — `str[0]` uppercases `U+2068` (a silent no-op!).
   - Naive "first cased character" (`ToCased`) corrupts <span class="str">49ers</span> $\to$ ❌ **<span class="str">49Ers</span>** and Dutch <span class="str">'s-Gravenhage</span> $\to$ ❌ **<span class="str">'S-Gravenhage</span>** (instead of <span class="str">'s-Gravenhage</span>).

---

## JS Bugs (2): RegExp `\b\w` & Trailing `.toLowerCase()` Destruction

1. **ASCII-Only RegExp (`str.replace(/\b\w/g, c => c.toUpperCase())`):**
   - In JS RegExp (even with `/u`), `\b` and `\w` match **only ASCII `[A-Za-z0-9_]`** ([angular/angular#23267](https://github.com/angular/angular/issues/23267)):
   - Every accented character is treated as a *non-word* character, creating a false word boundary immediately after it:
     - <span class="str">éclair</span> $\to$ ❌ **<span class="str">éClair</span>**; <span class="str">février</span> $\to$ ❌ **<span class="str">FéVrier</span>**; <span class="str">FOGÃO</span> $\to$ ❌ **<span class="str">FogãO</span>**
   - Apostrophes also trigger `\b`: <span class="str">don't</span> $\to$ ❌ **<span class="str">Don'T</span>**; <span class="str">l'arbre</span> $\to$ ❌ **<span class="str">L'Arbre</span>**.

2. **Why `.slice(1).toLowerCase()` & Name Normalization Fail:**
   - Destroys inner proper nouns, acronyms, and brands:
     - <span class="str">Español de España</span> $\to$ ❌ **<span class="str">Español de españa</span>**
     - <span class="str">COVID-19</span> $\to$ ❌ **<span class="str">Covid-19</span>** ([angular/angular#41420](https://github.com/angular/angular/issues/41420)); <span class="str">iPhone</span> $\to$ ❌ **<span class="str">Iphone</span>**
   - Corrupts person names:
     - <span class="str">maría josé</span> $\to$ ❌ **<span class="str">María josé</span>** *(second given name lowercased)*
     - <span class="str">McDonald</span> $\to$ ❌ **<span class="str">Mcdonald</span>**; <span class="str">van der Berg</span> $\to$ ❌ **<span class="str">Van Der Berg</span>**

---

## CSS Gaps (1): `text-transform: capitalize` & `::first-letter`

<div class="columns">
<div>

### 1. `capitalize` Forces Every-Word Casing
In **1,000 CSS/Vue/TSX fragments** studied (from **1.7M+ files**), `.capitalize` is applied to translated headings, weather, dates, and language pickers:
```html
<h2 class="text-capitalize">{{ $t('our_services') }}</h2>
<span class="capitalize">{{ weather.description }}</span>
<p class="capitalize">{{ date.toLocaleDateString('es') }}</p>
```
- **French heading:** <span class="str">nos services numériques</span> $\to$ ❌ **<span class="str">Nos Services Numériques</span>** *(wants <span class="str">Nos services numériques</span>)*
- **Spanish/French weather (1,908 files):** <span class="str">cielo claro</span> $\to$ ❌ **<span class="str">Cielo Claro</span>**; <span class="str">ciel dégagé</span> $\to$ ❌ **<span class="str">Ciel Dégagé</span>**
- **Language pickers (`immich`):** <span class="str">español de España</span> $\to$ ❌ **<span class="str">Español De España</span>**

</div>
<div>

### 2. Why `::first-letter` Doesn't Save Us
```css
/* Ignored on inline <span>/<a> without inline-block! */
.label::first-letter { text-transform: uppercase; }
```
- **Block containers only (`CSS Pseudo-Elements 4 §2.2`):** Ignored on inline `<span>`, `<a>`, `<label>`.
- **`uppercase` $\neq$ Titlecase:** Strips Greek initial *tonos* (<span class="str">Άνθρωπος</span> $\to$ ❌ **<span class="str">Ανθρωπος</span>**) and outputs Georgian *Mtavruli* (<span class="str">Თბილისი</span>).
- **Engine bugs with `::first-letter { text-transform: capitalize }`:** Fails in Blink on Dutch <span class="str">ijsland</span> $\to$ ❌ **<span class="str">Ijsland</span>** ([crbug.com/1172333](https://crbug.com/1172333)) and `"«\u00A0bonjour"` ([crbug.com/41270370](https://crbug.com/41270370)).

</div>
</div>

## CSS Gaps (2): Accessibility Leaks, Clipboard, & Non-CSS Surfaces

1. **Screen Readers & Accessibility Tree ([w3c/accname#239](https://github.com/w3c/accname/issues/239), [w3c/csswg-drafts#10732](https://github.com/w3c/csswg-drafts/issues/10732)):**
   - CSS `text-transform` leaks into the computed accessible name (`accname`):
     ```html
     <button style="text-transform: uppercase">Call us</button>
     ```
   - Screen readers announce ❌ **<span class="str">Call U.S.</span>** because `"US"` is read as an initialism!

2. **Clipboard & `element.innerText` Mutation ([webkit.org/b/43202](https://bugs.webkit.org/show_bug.cgi?id=43202)):**
   - Copying styled text or reading `element.innerText` bakes presentational CSS casing into the user's clipboard and application state.

3. **Non-CSS Surfaces Across the Web Platform:**
   - CSS cannot style strings in `document.title` (`<title>`), `<option>` elements in native `<select>` menus, `aria-label` attributes, `<canvas>` / WebGL text, or Web `Notification` payloads.

# Part 2: Contextual Capitalization
## Even With a Good Titlecase Algorithm, *When* Should You Apply It?

---

## Capitalization According to CLDR and Unicode

<div class="columns">
<div>

### Phase 1: Contextual Decision

**Input:** Locale, UI Context, Lexical Category
**Output:** Algorithm Choice *(via CLDR `<contextTransforms>`)*

_Example UI Contexts (`UTS #35` + UI):_
- **Middle of sentence** (`middle-of-sentence` — CLDR default)
- **Beginning of sentence** (`beginning-of-sentence`)
- **Menu / list item** (`uiListOrMenu`)
- **Standalone label / header** (`stand-alone`)
- **Headline / Title** (Editorial UI chrome)

_Example Lexical Categories:_
- **CLDR nouns:** Month/day name, Language/region name, Relative date (<span class="str">yesterday</span>), Currency/unit
- **Person name** (Always `no-change`)
- **Prose / UI label**

</div>
<div>

### Phase 2: Case Map Execution

**Input:** Locale, String, Algorithm Choice
**Output:** Case-Mapped String *(Part 1!)*

_Algorithm Choices:_
- **`no-change`:** Leave string as-is *(mid-sentence, Swedish standalone months, French menu months, person names)*
- **`First-Word Titlecase` (`titlecase-firstword`):** `ICU4X TitlecaseMapper::titlecase_segment` / `ICU4C U_TITLECASE_WHOLE_STRING` with `TrailingCase::Unchanged` & `LeadingAdjustment::Auto` *(zero `BreakIterator` cost!)*
- **`Sentence Case`:** First-Word Titlecase per `UAX #29` sentence
- **`Every-Word Titlecase`:** Titlecase per `UAX #29` word (CSS `capitalize`)
- **`Editorial Title Case`:** Every-Word Titlecase skipping stopwords (<span class="str">of</span>, <span class="str">the</span>, <span class="str">de</span>)

</div>
</div>

---

## Why Unconditional First-Word Casing Fails (`<contextTransforms>`)

Developers who notice CSS `capitalize` hits every word switch to JS (as Spanish devs noted in code comments: *"Con `capitalize` de CSS quedaba <span class="str">Septiembre De 2026</span>"*) and hardcode **First-Word Casing for every locale and UI slot**:

```js
// Found across dozens of GitHub calendar, datepicker, and i18n utilities:
function formatMonthLabel(date, locale) {
  const s = date.toLocaleDateString(locale, { month: 'long', year: 'numeric' });
  return capitalizeFirstWord(s, locale); // ❌ Runs for EVERY locale & UI context!
}
```

**Why unconditionally applying First-Word Titlecase breaks localized UI across locales and contexts:**

| Item & UI Context | Spanish (`es`) | French (`fr`) | Czech (`cs`) | Swedish (`sv`) / Finnish (`fi`) |
| :--- | :---: | :---: | :---: | :---: |
| **Month in Calendar Header (`stand-alone`)** | <span class="str">Septiembre</span> (Cap) | <span class="str">Septembre</span> (Cap) | **<span class="str">září</span> (`no-change`)** | **<span class="str">september</span> / <span class="str">syyskuu</span> (`no-change`)** |
| **Month in `<select>` Menu (`uiListOrMenu`)** | <span class="str">Septiembre</span> (Cap) | **<span class="str">septembre</span> (`no-change`)** | <span class="str">Září</span> (Cap) | **<span class="str">september</span> / <span class="str">syyskuu</span> (`no-change`)** |
| **Language in `<select>` Menu (`uiListOrMenu`)** | <span class="str">Español</span> (Cap) | <span class="str">Français</span> (Cap) | <span class="str">Čeština</span> (Cap) | <span class="str">Svenska</span> / <span class="str">Suomi</span> (Cap) |
| **Language Standalone (`stand-alone`)** | <span class="str">Español</span> (Cap) | **<span class="str">français</span> (`no-change`)** | <span class="str">Čeština</span> (Cap) | <span class="str">Svenska</span> / **<span class="str">suomi</span> (`no-change`)** |
| **In Running Text (`middle-of-sentence`)** | **<span class="str">septiembre</span>** | **<span class="str">septembre</span>** | **<span class="str">září</span>** | **<span class="str">september</span> / <span class="str">syyskuu</span>** |

## How `Intl` Leaves Browsers & Locales Inconsistent Today

CLDR stores terms in **middle-of-sentence** form (<span class="str">enero</span>, <span class="str">janvier</span>, <span class="str">español</span>, <span class="str">русский</span>) and uses `<contextTransforms>` (compiled in ICU to a tiny 2-bit flag vector per category) for UI contexts. Because `ECMA-402` has not exposed context ([tc39/ecma402#355](https://github.com/tc39/ecma402/issues/355)):

<div class="columns">
<div>

### 1. Cross-Browser Divergence in `Intl.DisplayNames`
- **V8 (Chrome):** passes `UDISPCTX_CAPITALIZATION_NONE`
- **SpiderMonkey (Firefox) & JSC (Safari):** pass `UDISPCTX_CAPITALIZATION_FOR_STANDALONE`

```js
new Intl.DisplayNames(['es'], { type: 'language' })
  .of('es');
// Chrome:         "español" (lowercase)
// Firefox/Safari: "Español" (Capitalized)

new Intl.DisplayNames(['fr'], { type: 'language' })
  .of('fr');
// ALL browsers:   "français" (lowercase!)
// Why? CLDR 'fr' (and 'fi', 'da') only capitalizes
// languages in uiListOrMenu, not stand-alone!
```

</div>
<div>

### 2. Real-World Pain in Production UIs
- **Perplexity Language Picker ([tc39/ecma402#355](https://github.com/tc39/ecma402/issues/355)):**
  Across ~50 interface languages in Chrome, `Intl.DisplayNames` returns **27 lowercase** (<span class="str">español</span>, <span class="str">français</span>, <span class="str">русский</span>, <span class="str">polski</span>, <span class="str">čeština</span>, <span class="str">suomi</span>) and **~23 capitalized** (<span class="str">English</span>, <span class="str">Deutsch</span>, <span class="str">Nederlands</span>, <span class="str">Türkçe</span>).
- **Project Fluent ([projectfluent/fluent#299](https://github.com/projectfluent/fluent/issues/299)) & FormatJS ([#1527](https://github.com/formatjs/formatjs/issues/1527)):**
  Maintainers declined to add custom casing filters, pointing to [tc39/ecma402#355](https://github.com/tc39/ecma402/issues/355) as the missing platform primitive.

</div>
</div>

## Architecture: Why `Intl` Owns Phase 1+2 While CSS & `String` Own Phase 2

<div class="columns">
<div>

### 1. Why Can't CSS or `String` Do Phase 1? When Should Phase 1 Be Skipped?
- **Phase 1 requires the *Lexical Category*, which CSS and `String` do not have:**
  - In a French `<select>` menu (`uiListOrMenu`), a **language** (<span class="str">français</span> $\to$ **<span class="str">Français</span>**) is capitalized, but a **month** (<span class="str">septembre</span> $\to$ **<span class="str">septembre</span>**) is *not*!
  - In a Swedish header (`stand-alone`), a **month** (<span class="str">september</span>) stays lowercase, while a **prose heading** (<span class="str">Välj datum</span>) is capitalized.
  - CSS and `String` only see raw text (<span class="str">"septembre"</span>)—only `Intl` knows it is formatting a `month` vs. a `language` and can look up CLDR `<contextTransforms>`.
- **When Phase 1 is skipped (~90% of sites):**
  - For **prose, UI labels, headings, and error toasts**, there is no CLDR noun-category exception table: **the UI designer/author *is* Phase 1** (they already chose `First-Word Titlecase`, `Sentence Case`, or `Editorial Title Case`) and only needs **Phase 2** execution!

</div>
<div>

### 2. What Belongs in CSS vs. What Belongs in JS?
- **Belongs in CSS (`css-text` — Phase 2):**
  - Purely **presentational styling** of DOM block/heading elements where the HTML holds canonical text, visual casing adapts to layout/design, and box boundaries match label/sentence boundaries.
- **Belongs in `Intl` ([tc39/ecma402#355](https://github.com/tc39/ecma402/issues/355) — Phase 1 + 2):**
  - Formatting **category-known CLDR nouns** (`DateTimeFormat`, `DisplayNames`, `RelativeTimeFormat`) where casing depends on `Locale × UI Context × Category`.
- **Belongs in JS `String` / `Segmenter` ([tc39/ecma402#294](https://github.com/tc39/ecma402/issues/294) — Phase 2):**
  - **Non-CSS sinks** (`<title>`, `<option>`, `aria-label`, `<canvas>`, `Notification`), **i18n pipelines** (MF2 [#38](https://github.com/unicode-org/message-format-wg/issues/38)), **inline spans** where CSS box boundaries don't match sentences, and **userland Editorial Title Case** (`Intl.Segmenter` + [#294](https://github.com/tc39/ecma402/issues/294)).

</div>
</div>

## Solution Track 1A: Sentence / First-Word Casing in CSS ([#8893](https://github.com/w3c/csswg-drafts/issues/8893))

What [w3c/csswg-drafts#8893](https://github.com/w3c/csswg-drafts/issues/8893) proposes — and the **hard CSS architectural challenges** we must grapple with:

<div class="columns">
<div>

### The Goal: Declarative Phase 2 First-Word / Sentence Case
- Give authors a declarative `text-transform` mode that applies **Unicode `Titlecase_Mapping` + `TrailingCase::Unchanged` + `LeadingAdjustment::Auto`** to the start of a text scope instead of every word:
  - Fixes translated headings, chips, and weather phrases (<span class="str">Nos services numériques</span>, <span class="str">Cielo claro</span>) without `display: inline-block` `::first-letter` hacks.
  - Preserves Greek initial *tonos* (<span class="str">Άνθρωπος</span>), Dutch <span class="str">IJsland</span>, and Georgian identity (<span class="str">თბილისი</span>).

</div>
<div>

### Open CSS & DOM Challenges to Resolve
1. **Inline `<span>` Fragmentation:** An inline `<span class="...">` may or may not be a full sentence — it might sit mid-sentence (`<p>See <span>our guide</span></p>`), or one sentence might be split across multiple sibling `<span>`s. (This is why `::first-letter` was restricted to block containers!)
2. **Sentence Boundary Ambiguity (`UAX #29`):** In multi-sentence mode, abbreviations (<span class="str">Dr. Smith</span>, <span class="str">e.g. apples</span>) trigger false sentence breaks without locale dictionaries.
3. **Editorial Title Case ([w3c/csswg-drafts#12526](https://github.com/w3c/csswg-drafts/issues/12526)):** Stopwords (<span class="str">of</span>, <span class="str">the</span>) are style-guide-specific (AP vs. Chicago) and don't belong in browser engines (cf. custom `@text-transform` [#3132](https://github.com/w3c/csswg-drafts/issues/3132)).

</div>
</div>

## Solution Track 1B: CSS Tailoring Interop, Performance, & Leaks

Even for existing `text-transform` values, browsers need alignment on Phase 2 execution and accessibility:

1. **Zero-Regression Engine Fast Path ([crbug.com/420998400](https://crbug.com/420998400), [crbug.com/41248541](https://crbug.com/41248541)):**
   - When Blink switched `text-transform: capitalize` to ICU `CaseMap::toTitle` to fix Dutch <span class="str">IJ</span>, per-run `BreakIterator` instantiation caused a **4.3% Speedometer 3 regression**.
   - **Solution:** Cache `BreakIterator` instances per locale for every-word `capitalize`, and use **zero-breaker single-span titlecasing** (`ICU4X titlecase_segment` / `ICU4C U_TITLECASE_WHOLE_STRING`) for first-word transforms.

2. **Align Locale Tailorings & Word Boundaries Across Engines:**
   - **Dutch (`nl`):** <span class="str">ijsland</span> $\to$ **<span class="str">IJsland</span>** and elision <span class="str">'s-Gravenhage</span> (including in `::first-letter` [[crbug.com/1172333](https://crbug.com/1172333)]).
   - **Irish (`ga`):** Prefix mutations (<span class="str">an t-uisce</span> $\to$ **<span class="str">AN tUISCE</span>**, currently Gecko-only).
   - **Word boundaries:** Align `UAX #29` behavior on <span class="str">foo.bar</span> and Catalan *punt volat* (<span class="str">cancel·lar</span>).

3. **Stop Accessibility & Clipboard Leaks:**
   - Prevent visual `text-transform` from mutating `accname` ([w3c/accname#239](https://github.com/w3c/accname/issues/239), [w3c/csswg-drafts#10732](https://github.com/w3c/csswg-drafts/issues/10732)) or Safari plain-text clipboard ([webkit.org/b/43202](https://bugs.webkit.org/show_bug.cgi?id=43202)).

## Solution Track 2A: Contextual Capitalization in `Intl` ([#355](https://github.com/tc39/ecma402/issues/355))

For CLDR nouns (`DateTimeFormat`, `DisplayNames`, `RelativeTimeFormat`), expose `{ capitalization }` so `Intl` executes **Phase 1 (`<contextTransforms>`) + Phase 2 (`titlecase-firstword`)**:

```js
// 1. Standalone calendar header:
new Intl.DateTimeFormat(locale, {
  month: 'long', year: 'numeric',
  capitalization: 'standalone',
  // 'middle-of-sentence' (default) | 'beginning-of-sentence' | 'ui-list-or-menu' | 'standalone'
}).format(date);
// es -> "Septiembre de 2026"   (first word titlecased, "de" stays lowercase!)
// sv -> "september 2026"       (respects Swedish no-change rule!)

// 2. Language picker menu:
new Intl.DisplayNames([locale], {
  type: 'language',
  capitalization: 'ui-list-or-menu',
}).of('es-ES');
// fr -> "Espagnol d’Espagne"   (capitalized in menus, lowercase in running text)
```

- **Resolves Chrome vs. Firefox/Safari divergence** on `Intl.DisplayNames` by standardizing `'middle-of-sentence'` as the default while giving UI authors explicit control.

## Solution Track 2B: Co-Requisite CLDR `<contextTransforms>` & ICU Audit

Standardizing `{ capitalization }` in [tc39/ecma402#355](https://github.com/tc39/ecma402/issues/355) only works if CLDR's `<contextTransforms>` data matches native-speaker UI expectations. Our GitHub call-site audit exposed three concrete upstream gaps:

1. **Portuguese (`pt`) Months (Missing in `pt.xml`):**
   - Portuguese was the **#1 locale in our GitHub study** (27 `pt-BR` call sites manually capitalizing <span class="str">Setembro de 2026</span> in calendar headers).
   - Yet CLDR `pt.xml` defines `<contextTransforms>` for `day-*` and `relative`, **but completely omits `month-*`**!

2. **Language Pickers (`languages` Missing `uiListOrMenu` in 11+ European Locales):**
   - Half of the 27 lowercase languages reported by Perplexity in [tc39/ecma402#355](https://github.com/tc39/ecma402/issues/355) lack `<contextTransformUsage type="languages">` in CLDR: **`pl` (<span class="str">polski</span>), `hu` (<span class="str">magyar</span>), `ca` (<span class="str">català</span>), `ro` (<span class="str">română</span>), `bg` (<span class="str">български</span>), `sr`, `sl`, `lt`, `lv`, `et`, `is`**.

3. **Relative Dates (`relative` in CLDR & ICU4C `reldatefmt.cpp`):**
   - CLDR `fr` (<span class="str">hier</span>), `es` (<span class="str">ayer</span>), and `it` (<span class="str">ieri</span>) omit `<contextTransformUsage type="relative">`.
   - In ICU4C (`reldatefmt.cpp:816`), `RelativeDateTimeFormatter` only checks `CAPITALIZATION_FOR_BEGINNING_OF_SENTENCE` and **ignores `STANDALONE` and `UI_LIST_OR_MENU`**!

## Solution Track 3A: Single-Span Case Mapping Primitive in JS ([#294](https://github.com/tc39/ecma402/issues/294))

How do we fix the **90%+ of JS human-text call sites** that transform non-`Intl` strings (API descriptions, error toasts, `<title>`, `<option>`, `aria-label`, MF2 messages)?

```js
// 1. Direct Phase 2 replacement for s.charAt(0).toUpperCase() + s.slice(1)
// (Default: trailingCase: 'unchanged', leadingAdjustment: 'auto')
str.toLocaleCapitalize(locale);
// "cielo claro" ('es')     -> "Cielo claro"
// "«bonjour»" ('fr')       -> "«Bonjour»"
// "\u2068lundi\u2069"      -> "\u2068Lundi\u2069"
// "ijsland" ('nl')         -> "IJsland"
// "'s-Gravenhage" ('nl')   -> "'s-Gravenhage"
// "თბილისი" ('ka')         -> "თბილისი" (no-op!)
// "ǆep" ('hr')             -> "ǅep"

// 2. Composes with Intl.Segmenter for ~1KB userland Editorial Title Case:
const segs = new Intl.Segmenter(locale, { granularity: 'word' });
let out = '';
for (const { segment, isWordLike } of segs.segment(str)) {
  out += isWordLike && !STOP.has(segment.toLocaleLowerCase(locale))
    ? segment.toLocaleCapitalize(locale, { trailingCase: 'lower' })
    : segment;
}
```

## Solution Track 3B: Resolving All 4 TG2 Vendor Objections ([#294](https://github.com/tc39/ecma402/issues/294))

Scoping [tc39/ecma402#294](https://github.com/tc39/ecma402/issues/294) to a **single-span Phase 2 primitive** (`U_TITLECASE_WHOLE_STRING` / `ICU4X titlecase_segment`) resolves every objection raised in the July 2020 TC39-TG2 discussion:

1. **Objection 1: *"Shouldn't this just be done in CSS?"***
   - CSS cannot reach `<title>`, `<option>`, `aria-label`, `<canvas>`, `Notification`, or MessageFormat 2 ([unicode-org/message-format-wg#38](https://github.com/unicode-org/message-format-wg/issues/38)); inline `<span>` sentence styling is ambiguous in CSS; and CSS `text-transform` leaks into `accname` ([w3c/accname#239](https://github.com/w3c/accname/issues/239)) and the clipboard ([webkit.org/b/43202](https://bugs.webkit.org/show_bug.cgi?id=43202)).

2. **Objection 2: *"What about <span class="str">MacDonald</span> and <span class="str">iPhone</span>?"***
   - Default `trailingCase: 'unchanged'` (`U_TITLECASE_NO_LOWERCASE`) only transforms the leading titlecase grapheme and **never lowercases** <span class="str">MacDonald</span>, <span class="str">iPhone</span>, <span class="str">COVID-19</span>, or <span class="str">España</span> (matching 93.5% of GitHub call sites).

3. **Objection 3: *"Word segmentation (`BreakIterator`) is slow and fragile"***
   - Single-span titlecasing requires **zero word segmentation**, avoiding Blink's 4.3% Speedometer 3 regression ([crbug.com/420998400](https://crbug.com/420998400)) and word-break edge cases (<span class="str">foo.bar</span>).

4. **Objection 4: *"Editorial Title Case stopwords are subjective"***
   - Stopword lists (AP vs. Chicago) stay in userland libraries via `Intl.Segmenter` + [#294](https://github.com/tc39/ecma402/issues/294); avoiding the method name `"titleCase"` prevents confusion with multi-word Editorial Title Case.
