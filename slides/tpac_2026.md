# Capitalization, Titlecasing, and Presentational Case Mapping

## Shane F. Carr (@sffc)
### W3C TPAC 2026 Breakout (#80) — CSSWG × W3C i18n × TC39-TG2

---

## Three Real-World Casing Disasters on the Web Today

1. **CSS `text-transform: capitalize` on Localized Dates & UI (`FullCalendar`, `immich` 70k⭐):**
   - Spanish date header: `"lunes, 12 de enero de 2026"` $\to$ ❌ **`"Lunes, 12 De Enero De 2026"`**
   - Russian calendar: `"сентябрь 2026 г."` $\to$ ❌ **`"Сентябрь 2026 Г."`**
   - Language picker: `"español de España"` $\to$ ❌ **`"Español De España"`**; `"srpski (latinica)"` $\to$ ❌ **`"Srpski (Latinica)"`**

2. **JS `str.charAt(0).toUpperCase() + str.slice(1)` on Non-ASCII Scripts (100k+ GitHub files):**
   - **Georgian (`ka`):** `"თბილისი"` (*Tbilisi*) $\to$ ❌ **`"Თბილისი"`** *(glues an ALL-CAPS Mtavruli capital onto lowercase Mkhedruli — Georgian does not capitalize words!)*
   - **Dutch (`nl`):** `"ijsland"` (*Iceland*) $\to$ ❌ **`"Ijsland"`** *(misses the `"IJ"` digraph even with `toLocaleUpperCase('nl')`)*
   - **Adlam / Non-BMP DOM split:** `<span>{str[0].toUpperCase()}</span>{str.slice(1)}` $\to$ ❌ **`"𞤢𞤲𞤣"`** *(tears UTF-16 surrogate pair into `U+FFFD U+FFFD`)*

3. **JS RegExp `\b\w` & CSS Screen Reader Leaks (`Angular #23267`, `w3c/accname#239`):**
   - `str.replace(/\b\w/g, c => c.toUpperCase())`: `"février"` $\to$ ❌ **`"FéVrier"`**; `"éclair"` $\to$ ❌ **`"éClair"`**; `"don't"` $\to$ ❌ **`"Don'T"`** (`\b\w` is ASCII-only!)
   - `<button style="text-transform: uppercase">Call us</button>` $\to$ Screen readers announce ❌ **`"Call U.S."`**

---

## Untangling Terminology

Standards discussions often stall because **"capitalize"** and **"titlecase"** refer to one of several distinct operations:

| Term | Precise Meaning | Examples |
| :--- | :--- | :--- |
| **Character Titlecase Mapping** | Maps a single letter/digraph according to Unicode titlecase rules (`Lt`) | `ǆ` $\to$ `ǅ`, `ﬁ` $\to$ `Fi`<br/>Dutch `ij` $\to$ `IJ`, Georgian `ა` $\to$ `ა` (no-op) |
| **First-Letter Uppercase** | A broken, naive method (`s[0].toUpperCase() + s.slice(1)`) that many developers use to implement titlecasing | `"ijsland"` $\to$ ❌ `"Ijsland"`<br/>`"თბილისი"` $\to$ ❌ `"Თბილისი"` |
| **First-Word Titlecase** | Apply titlecase mapping to the first \~letter of a string (`titlecase-firstword`, trailing case unchanged) | `"español de España"` $\to$ `"Español de España"`<br/>`"«bonjour»"` $\to$ `"«Bonjour»"` |
| **Sentence Case** | Same as First-Word Titlecase but applied to every sentence in a string | `"hello world. ¡hola mundo!"` $\to$ `"Hello world. ¡Hola mundo!"` |
| **Every-Word Titlecase** | Apply titlecase mapping to the first \~letter of every \~word in a string (CSS `capitalize`) | `"español de España"` $\to$ `"Español De España"`<br/>`"out-of-the-box"` $\to$ `"Out-Of-The-Box"` |
| **Editorial Title Case** | Same as Every-Word Titlecase but with style guide rules (AP / Chicago / APA) to skip stopwords ("of", "the", "de") | `"the war of the worlds"` $\to$ `"The War of the Worlds"` |
| **Contextual Capitalization** | Based on a _UI context_ and _category_, choose the correct casing algorithm (`<contextTransforms>`) | `"septembre"` (`fr` month) $\to$ `"Septembre"` in calendar header, `"septembre"` in menu |

## State in the Web Platform

<div class="columns">
<div>

### 1. CSS & HTML
- **`text-transform: capitalize;`**
  - Applies *Every-Word Titlecase* (`U_TITLECASE_NO_LOWERCASE`) to all text.
  - *Stopwords (`CSS Text 3 §2.1`):* Word boundaries are UA-dependent (`UAX #29` suggested); spec notes *"Authors cannot depend on `capitalize` to follow language-specific titlecasing conventions (such as skipping articles in English)"* — **no engine skips stopwords**.
- **`::first-letter`:** Block containers only (ignored on inline `<span>`, `<a>`).
- **HTML:** `autocapitalize` only hints mobile virtual keyboards; `<html lang>` is used by CSS **but ignored by JS `toLocaleUpperCase()`**.
- **Open CSS Issues:**
  - [w3c/csswg-drafts#8893](https://github.com/w3c/csswg-drafts/issues/8893) — First-Word / Sentence Case
  - [w3c/csswg-drafts#12526](https://github.com/w3c/csswg-drafts/issues/12526) — Editorial Title Case

</div>
<div>

### 2. JavaScript (`String` & `Intl`)
- **No native support** for titlecase mapping (`toUpperCase()` / `toLowerCase()` only).
- **`Intl` formatters** return a single default casing with **no UI context option**.
- **What developers do instead:**
  - **100,000+ GitHub files** (and **12,750+ `google3` files**) hardcode naive first-letter uppercase ([SO #1026069](https://stackoverflow.com/questions/1026069), **4.7M+ views**, baked into TypeScript `Capitalize<S>`, Vue, MUI, Angular, Closure).
  - **1.7M+ CSS/TSX/Vue files** apply `text-transform: capitalize`.
- **Open JS / `Intl` Issues:**
  - [tc39/ecma402#294](https://github.com/tc39/ecma402/issues/294) — Titlecase / Case Mapping in JS
  - [tc39/ecma402#355](https://github.com/tc39/ecma402/issues/355) — Contextual Capitalization in `Intl`

</div>
</div>

# Part 1: Bugs & Gaps in Applying Titlecase
## Why Naive JS & CSS Workarounds Fail Across Scripts

---

## Why Titlecase $\neq$ First-Letter Uppercase

<div class="columns">
<div>

### How Developers Do It Wrong Today
- **In JavaScript (`100k+` GitHub files):**
  ```js
  // Slices UTF-16 code unit 0 and uppercases it:
  const capitalize = s =>
    s.charAt(0).toUpperCase() + s.slice(1);
  ```
- **In CSS (`::first-letter` hack):**
  ```css
  /* Ignored on inline <span>/<a> without inline-block! */
  .label { display: inline-block; }
  .label::first-letter {
    text-transform: uppercase;
  }
  ```

</div>
<div>

### What True Titlecase Mapping Actually Requires
1. **Leading Adjustment (`Auto`):** Advance past `«`, `¿`, quotes, and Bidi isolates (`U+2068`); keep `"49ers"` & Dutch `"'s-Gravenhage"` intact.
2. **Unicode `Titlecase_Mapping` ($\neq$ `Uppercase`):** Code-point & grapheme awareness (surrogates, NFD combining marks), digraphs (`ǆ` $\to$ `ǅ`), ligatures (`ﬁ` $\to$ `Fi`), and **Georgian `ka` identity (no-op!)**.
3. **Locale Tailorings:** Dutch `ij` $\to$ `IJ`, Turkish `i` $\to$ `İ`, Greek initial *tonos* retention (`"άνθρωπος"` $\to$ `"Άνθρωπος"`, whereas `uppercase` strips accents $\to$ `"ΑΝΘΡΩΠΟΣ"`), Lithuanian dot removal, Irish `ga` prefixes.
4. **Trailing Case (`Unchanged`):** Preserve `"MacDonald"`, `"iPhone"`, `"España"`, `"COVID-19"`.

</div>
</div>

---

## Character & Script Failures: `str[0].toUpperCase()` Is Not Titlecase

`str[0].toUpperCase() + str.slice(1)` applies **`Uppercase_Mapping` to UTF-16 code unit 0** instead of **`Titlecase_Mapping` to the first word**:

| Script / Rule | Input | `str[0].toUpperCase() + str.slice(1)` | Correct Titlecase | Why It Fails (Verified Live in V8) |
| :--- | :--- | :--- | :--- | :--- |
| **Georgian (`ka`)** | `"თბილისი"` (*Tbilisi*)<br>`"იანვარი"` (*January*) | ❌ **`"Თბილისი"`**<br>❌ **`"Იანვარი"`** | **`"თბილისი"`**<br>**`"იანვარი"`** | Georgian has no word capitalization (`Titlecase_Mapping` = self; *Mtavruli* `Თ` is strictly ALL-CAPS!) |
| **Dutch `ij` (`nl`)** | `"ijsland"` (*Iceland*) | ❌ **`"Ijsland"`** *(even with `toLocaleUpperCase('nl')`!)* | **`"IJsland"`** | `str[0]` only passes `"i"`, hiding the `"ij"` digraph from the case mapper |
| **Serbo-Croatian (`Lt`)** | `"ǆep"` (*pocket*) | ❌ **`"Ǆep"`** (`DŽep`) | **`"ǅep"`** (`Džep`) | `U+01C6` maps to `Lt` `ǅ` (`U+01C5`), not `Lu` `Ǆ` (`U+01C4`) |
| **Ligatures & Armenian** | `"ﬁrst"`, `"ևս"` | ❌ **`"FIrst"`**, **`"ԵՒս"`** | **`"First"`**, **`"Եւս"`** | `SpecialCasing.txt` upper (`FI`, `ԵՒ`) $\neq$ title (`Fi`, `Եւ`) |
| **Greek Polytonic (`Lt`)** | `"ᾳδης"` (*Hades*) | ❌ **`"ΑΙδης"`** | **`"ᾼδης"`** | Upper expands *ypogegrammeni* to two capitals (`ΑΙ`); title uses *prosgegrammeni* (`ᾼ`) |
| **Turkish (`tr` / `az`)** | `"istanbul"` | ❌ **`"Istanbul"`** | **`"İstanbul"`** | `.toUpperCase()` is locale-blind, and `.toLocaleUpperCase()` ignores `<html lang="tr">`! |

## Surrogates, Leading Punctuation, `\b\w`, & Trailing Case

<div class="columns">
<div>

### 1. Surrogates, Combining Marks, & Leading Punctuation
- **UTF-16 Surrogates (9 bicameral scripts):** In **Adlam** (`"𞤢𞤤𞤢𞤲𞤣"` *Sunday*), **Deseret**, **Osage**, `str[0]` is a lone high surrogate (`\uD83A`) — `.toUpperCase()` is a **silent no-op** (`camelcase#117`), and `<span>{str[0]}</span>{str.slice(1)}` renders `U+FFFD`!
- **Lithuanian (`lt`) & NFD:** Slicing `str[0]` on `"i\u0307\u0303"` hides `\u0307`, leaving a double-dotted **`"I\u0307\u0303"`**.
- **Leading Punctuation & Elisions:** `"¿cómo estás?"`, `"«bonjour»"`, and **Fluent** Bidi isolates (`"\u2068lundi\u2069"`) fail at `str[0]`; naive `ToCased` corrupts `"49ers"` $\to$ **`"49Ers"`** and Dutch `"'s-Gravenhage"` $\to$ **`"'S-Gravenhage"`**.

</div>
<div>

### 2. RegExp `\b\w` & `.slice(1).toLowerCase()` Bugs
- **ASCII-Only RegExp (`str.replace(/\b\w/g, ...)`):**
  - `\b` and `\w` are **strictly ASCII** (`Angular #23267`):
  - `"éclair"` $\to$ ❌ **`"éClair"`**; `"février"` $\to$ ❌ **`"FéVrier"`**
  - `"FOGÃO"` $\to$ ❌ **`"FogãO"`**; `"don't"` $\to$ ❌ **`"Don'T"`**
- **Why `.slice(1).toLowerCase()` & Name Normalization Fail:**
  - Destroys `"Español de España"` $\to$ **`"Español de españa"`**, `"COVID-19"` $\to$ **`"Covid-19"`** (`angular#41420`), `"iPhone"` $\to$ **`"Iphone"`**.
  - Corrupts person names (`"maría josé"` $\to$ `"María josé"`, `"McDonald"` $\to$ `"Mcdonald"`, `"van der Berg"` $\to$ `"Van Der Berg"`).

</div>
</div>

## CSS Gaps: Every-Word Over-Casing, `::first-letter`, & Leaks

<div class="columns">
<div>

### 1. `text-transform: capitalize` Forces Every-Word Casing
In 1,000 CSS/Vue/TSX fragments studied, `.capitalize` is applied to translated headings, weather, dates, and language pickers:
```html
<h2 class="text-capitalize">{{ $t('our_services') }}</h2>
<span class="capitalize">{{ weather.description }}</span>
<p class="capitalize">{{ date.toLocaleDateString('es') }}</p>
```
- **French heading:** `"nos services numériques"` $\to$ ❌ **`"Nos Services Numériques"`** *(wants `"Nos services numériques"`)*
- **Spanish/French weather (1,908 files):** `"cielo claro"` $\to$ ❌ **`"Cielo Claro"`**; `"ciel dégagé"` $\to$ ❌ **`"Ciel Dégagé"`**
- **Language pickers (`immich`):** `"español de España"` $\to$ ❌ **`"Español De España"`**; `"norsk bokmål"` $\to$ ❌ **`"Norsk Bokmål"`**

</div>
<div>

### 2. Why `::first-letter` Fails & CSS Leaks
- **Why `.label::first-letter` doesn't save us:**
  - **Ignored on inline elements (`<span>`, `<a>`, `<label>`)** (`CSS Pseudo-Elements 4 §2.2`).
  - `::first-letter { text-transform: uppercase }` strips Greek initial *tonos* (`"Άνθρωπος"` $\to$ ❌ **`"Ανθρωπος"`**) and applies Georgian Mtavruli (`"Თბილისი"`).
  - Even `::first-letter { text-transform: capitalize }` fails in Blink on Dutch `"ijsland"` $\to$ **`"Ijsland"`** (`crbug.com/1172333`) and `"«\u00A0bonjour"` (`crbug.com/41270370`).
- **Accessibility, Clipboard, & Non-CSS Sinks:**
  - **Screen readers (`w3c/accname#239`):** `<button style="text-transform: uppercase">Call us</button>` $\to$ announced as **"Call U.S."**
  - **Clipboard & `innerText` (`webkit.org/b/43202`):** Mutates copied text.
  - **Cannot reach:** `<title>`, `<option>`, `aria-label`, `<canvas>`, `Notification`.

</div>
</div>

# Part 2: Contextual Capitalization
## Even With a Good Titlecase Algorithm, *When* Should You Apply It?

---

## Capitalization According to CLDR and Unicode

<div class="columns">
<div>

### Phase 1: Contextual Decision

**Input:** Locale, UI Context, Lexical Category
**Output:** Algorithm Choice *(via CLDR `<contextTransforms>`)*

_Example UI Contexts (`UTS #35` + UI):_
- **Middle of sentence** (`middle-of-sentence` — CLDR default)
- **Beginning of sentence** (`beginning-of-sentence`)
- **Menu / list item** (`uiListOrMenu`)
- **Standalone label / header** (`stand-alone`)
- **Headline / Title** (Editorial UI chrome)

_Example Lexical Categories:_
- **CLDR nouns:** Month/day name, Language/region name, Relative date (`"yesterday"`), Currency/unit
- **Person name** (Always `no-change`)
- **Prose / UI label**

</div>
<div>

### Phase 2: Case Map Execution

**Input:** Locale, String, Algorithm Choice
**Output:** Case-Mapped String *(Part 1!)*

_Algorithm Choices:_
- **`no-change`:** Leave string as-is *(mid-sentence, Swedish standalone months, French menu months, person names)*
- **`First-Word Titlecase` (`titlecase-firstword`):** `ICU4X TitlecaseMapper::titlecase_segment` / `ICU4C U_TITLECASE_WHOLE_STRING` with `TrailingCase::Unchanged` & `LeadingAdjustment::Auto` *(zero `BreakIterator` cost!)*
- **`Sentence Case`:** First-Word Titlecase per `UAX #29` sentence
- **`Every-Word Titlecase`:** Titlecase per `UAX #29` word (CSS `capitalize`)
- **`Editorial Title Case`:** Every-Word Titlecase skipping stopwords (`of`, `the`, `de`)

</div>
</div>

## Why Unconditional First-Word Casing Fails (`<contextTransforms>`)

Developers who notice CSS `capitalize` hits every word switch to JS (as Spanish devs noted in comments: *"Con `capitalize` de CSS quedaba 'Septiembre De 2026'"*) and hardcode **First-Word Casing for every locale and UI slot**:

```js
// Found across dozens of GitHub calendar, datepicker, and i18n utilities:
function formatMonthLabel(date, locale) {
  const s = date.toLocaleDateString(locale, { month: 'long', year: 'numeric' });
  return capitalizeFirstWord(s, locale); // ❌ Runs for EVERY locale & UI context!
}
```

**Why neither CSS (`text-transform: first-word`) nor unconditional JS can make the Phase 1 decision for `Intl` data:**

| Item & UI Context | Spanish (`es`) | French (`fr`) | Czech (`cs`) | Swedish (`sv`) / Finnish (`fi`) |
| :--- | :---: | :---: | :---: | :---: |
| **Month in Calendar Header (`stand-alone`)** | `Septiembre` (Cap) | `Septembre` (Cap) | **`září` (`no-change`)** | **`september` / `syyskuu` (`no-change`)** |
| **Month in `<select>` Menu (`uiListOrMenu`)** | `Septiembre` (Cap) | **`septembre` (`no-change`)** | `Září` (Cap) | **`september` / `syyskuu` (`no-change`)** |
| **Language in `<select>` Menu (`uiListOrMenu`)** | `Español` (Cap) | `Français` (Cap) | `Čeština` (Cap) | `Svenska` / `Suomi` (Cap) |
| **Language Standalone (`stand-alone`)** | `Español` (Cap) | **`français` (`no-change`)** | `Čeština` (Cap) | `Svenska` / **`suomi` (`no-change`)** |
| **In Running Text (`middle-of-sentence`)** | **`septiembre`** | **`septembre`** | **`září`** | **`september` / `syyskuu`** |

## How `Intl` Leaves Browsers & Locales Inconsistent Today

CLDR stores terms in **middle-of-sentence** form (`"enero"`, `"janvier"`, `"español"`, `"русский"`) and uses `<contextTransforms>` (compiled in ICU to a tiny 2-bit flag vector per category) for UI contexts. Because `ECMA-402` has not exposed context (`ecma402#355`):

<div class="columns">
<div>

### 1. Cross-Browser Divergence in `Intl.DisplayNames`
- **V8 (Chrome):** passes `UDISPCTX_CAPITALIZATION_NONE`
- **SpiderMonkey (Firefox) & JSC (Safari):** pass `UDISPCTX_CAPITALIZATION_FOR_STANDALONE`

```js
new Intl.DisplayNames(['es'], { type: 'language' })
  .of('es');
// Chrome:         "español" (lowercase)
// Firefox/Safari: "Español" (Capitalized)

new Intl.DisplayNames(['fr'], { type: 'language' })
  .of('fr');
// ALL browsers:   "français" (lowercase!)
// Why? CLDR 'fr' (and 'fi', 'da') only capitalizes
// languages in uiListOrMenu, not stand-alone!
```

</div>
<div>

### 2. Real-World Pain in Production UIs
- **Perplexity Language Picker (`ecma402#355`):**
  Across ~50 interface languages in Chrome, `Intl.DisplayNames` returns **27 lowercase** (`"español"`, `"français"`, `"русский"`, `"polski"`, `"čeština"`, `"suomi"`) and **~23 capitalized** (`"English"`, `"Deutsch"`, `"Nederlands"`, `"Türkçe"`).
- **Project Fluent (`fluent#299`) & FormatJS (`#1527`):**
  Maintainers declined to add custom casing filters, pointing to `ecma402#355` as the missing platform primitive.

</div>
</div>

# Part 3: Empirical Call-Site Study & Cohesive Solutions
## Matching Web Platform Layers to Phase 1 and Phase 2

---

## What Are Developers Actually Capitalizing? (GitHub Study)

Across **563 classified JS hits** (400 real call sites) + **~190 localized `Intl` call sites** + **1,000 CSS `.capitalize` fragments** + **2,000+ multilingual human-text lines**:

| What Is Being Capitalized | Share of JS Sample (+ CSS Usage) | Which Phase & Platform Primitive It Needs |
| :--- | :---: | :--- |
| **Internal keys/enums/statuses $\to$ UI labels, chips, tabs, headers, & translated strings (`$t('files')`)** | **51% of JS hits**<br>*(+ 33% of Vue `$t()` `.capitalize`)* | **Phase 2 (`titlecase-firstword`):** CSS `text-transform: first-word` (`#8893`) or JS (`#294`, `trailingCase: 'unchanged'`) |
| **API/DB phrases (`weather[0].description`), Go/Rust `error.message` toasts, transcripts, MF2** | **14.5% of JS hits**<br>*(1,908 weather + 106 error files; 0% lower tail!)* | **Phase 2 in JS (`#294`):** Single-span capitalization with `leadingAdjustment: 'auto'` & `trailingCase: 'unchanged'` |
| **`Intl` / date-library outputs (`DateTimeFormat`, `DisplayNames`, `RelativeTimeFormat`)** | **~1% random JS**<br>*(~10–15% TS file ceiling + ~25–30% of CSS date/calendar hits)* | **Phase 1 + 2 in `Intl` (`#355`):** CLDR `<contextTransforms>` (`standalone`, `ui-list-or-menu`, `beginning-of-sentence`) + **CLDR data audit** |
| **Person & place names (`nombre`, `prenom`, `isim`)** | **6.5% of JS hits**<br>*(only group using `.toLowerCase()`!)* | **`no-change`:** Do not case-normalize names; use UTS #35 Part 8 `initialPattern` (`Intl.PersonNames`) for initials |
| **Code / identifier generation (`PascalCase`, `on${Key}`)** | **26% of JS hits** | ASCII `s[0].toUpperCase() + s.slice(1)` *(locale-insensitive, already works)* |

> **Key Takeaway:** Neither `Intl` (`#355`), nor CSS (`#8893`), nor a JS primitive (`#294`) can solve this alone—each covers a distinct slice of the Web, and all three share the **same Phase 2 execution**.

## Solution Track 1: CSS (`css-text`) & Accessibility Alignment (Phase 2)

<div class="columns">
<div>

### 1. Standardize `text-transform: first-word` / `sentence` (`csswg-drafts#8893`)
- Direct declarative primitive for **First-Word Titlecase** (`titlecase-firstword`):
  - Applies Unicode `Titlecase_Mapping` + `TrailingCase::Unchanged` + `LeadingAdjustment::Auto` to the first word of an element.
  - **Works on inline elements (`<span>`, `<a>`, `<label>`)** as well as blocks — eliminating `display: inline-block` `::first-letter` hacks and Greek *tonos* / Georgian *Mtavruli* bugs.
  - Replaces `.capitalize` on UI headings, chips, badges, and translated strings (`"Nos services numériques"`).
- *What about Editorial Title Case (`#12526`)?* Stop words (`of`, `the`) are style-guide-specific (AP vs. Chicago); leave to userland or custom `@text-transform` (`#3132`).

</div>
<div>

### 2. Fix Tailoring Interop, Perf, & Leaks
- **Shared segment fast-path:** Avoid Blink's 4.3% Speedometer 3 regression (`crbug.com/420998400` when shipping Dutch `IJ` in `crbug.com/41248541`) by caching `BreakIterator` for `capitalize` and using zero-breaker segment titlecasing (`ICU4X titlecase_segment` / `ICU4C U_TITLECASE_WHOLE_STRING`) for `first-word`.
- **Language tailorings & word boundaries:** Align engines on Dutch `IJ`, Irish `ga` prefix mutations (`an t-uisce` $\to$ `AN tUISCE`, currently Gecko-only), and UAX #29 word boundaries (`foo.bar`, `cancel·lar`).
- **Fix Accessibility & Clipboard Leaks:** Do not expose visual `text-transform` mutations to `accname` (`w3c/accname#239`) or Safari plain-text clipboard (`webkit.org/b/43202`).

</div>
</div>

## Solution Track 2: Contextual Capitalization in `Intl` (`#355`) (Phase 1 + 2)

<div class="columns">
<div>

### 1. Expose `capitalization` Option in `Intl`
For CLDR nouns (`DateTimeFormat`, `DisplayNames`, `RelativeTimeFormat`), **only `Intl` knows the lexical category** needed for Phase 1:

```js
// Standalone calendar header:
new Intl.DateTimeFormat(locale, {
  month: 'long', year: 'numeric',
  capitalization: 'standalone',
  // 'middle-of-sentence' (default) | 'beginning-of-sentence'
  // | 'ui-list-or-menu' | 'standalone'
}).format(date);
// es -> "Septiembre de 2026"
// sv -> "september 2026" (respects Swedish no-change!)

// Language picker menu:
new Intl.DisplayNames([locale], {
  type: 'language',
  capitalization: 'ui-list-or-menu',
}).of('es-ES');
// fr -> "Espagnol d’Espagne" (vs "espagnol d’Espagne")
```
- Resolves Chrome vs. Firefox/Safari `Intl.DisplayNames` divergence by specifying `'middle-of-sentence'` as the default.

</div>
<div>

### 2. Co-Requisite: CLDR & ICU Data Audit
Our GitHub call-site audit revealed missing CLDR `<contextTransforms>` flags where native speakers expect capitalization:

### Single-Span Primitive + `Intl.Segmenter`
```js
// 1. Direct replacement for s[0].toUpperCase() + s.slice(1)
// (Default: trailingCase: 'unchanged', leadingAdjustment: 'auto')
str.toLocaleCapitalize(locale);
// "cielo claro" ('es')     -> "Cielo claro"
// "«bonjour»" ('fr')       -> "«Bonjour»"
// "\u2068lundi\u2069"      -> "\u2068Lundi\u2069"
// "ijsland" ('nl')         -> "IJsland"
// "'s-Gravenhage" ('nl')   -> "'s-Gravenhage"
// "თბილისი" ('ka')         -> "თბილისი" (no-op!)
// "ǆep" ('hr')             -> "ǅep"

// 2. Composes with Intl.Segmenter for 1KB userland Title Case:
const segs = new Intl.Segmenter(locale, { granularity: 'word' });
let out = '';
for (const { segment, isWordLike } of segs.segment(str)) {
  out += isWordLike && !STOP.has(segment.toLocaleLowerCase(locale))
    ? segment.toLocaleCapitalize(locale, { trailingCase: 'lower' })
    : segment;
}
```

<div>

### Resolves All 4 TG2 Vendor Objections
1. **Why not CSS-only?** Non-CSS sinks (`<title>`, `<option>`, `aria-label`, `<canvas>`, `Notification`), MF2 functions (`message-format-wg#38`), and avoiding `accname`/clipboard leaks.
2. **`MacDonald` & `iPhone` preserved:** Default `trailingCase: 'unchanged'` never lowercases `"MacDonald"`, `"iPhone"`, `"COVID-19"`, or `"España"`.
3. **Zero `BreakIterator` regression:** Single-span default (`U_TITLECASE_WHOLE_STRING` / `ICU4X titlecase_segment`) requires **no word segmenter**, avoiding Blink's 4.3% Speedometer 3 regression.
4. **Stop words stay in userland:** Style-guide rules (AP vs. Chicago) don't bloat browser engines; method name avoids the overloaded term `"titleCase"`.

## Summary: Matching Each Use Case to the Right Tool

| Real-World Use Case (from GitHub Study) | Broken Code Today | Proposed Platform Solution |
| :--- | :--- | :--- |
| **Declarative UI headings, chips, badges, inline `<span>`s, translated labels** (`$t('...')`, status labels) | `text-transform: capitalize` (forces every-word casing onto `fr`/`es`/`no`) or block-only `::first-letter` | **CSS `text-transform: first-word` / `sentence` (`#8893`)** + engine tailoring & `accname` fixes |
| **`Intl` dates, months, weekdays, languages, relative time in headers & menus** | `cap(date.toLocaleDateString(...))` or CSS `.capitalize` (ignores `sv`/`fr`/`cs` `no-change` rules) | **`Intl` `{ capitalization: 'standalone' \| 'ui-list-or-menu' \| ... }` (`ecma402#355`)** + CLDR `<contextTransforms>` audit |
| **Non-`Intl` strings in JS: toasts, API phrases (`weather.description`), MF2, `<title>`, `<option>`, `aria-label`** | `s.charAt(0).toUpperCase() + s.slice(1)` (breaks `ka`, `nl` `IJ`/`'s-`, `tr` `İ`, `Lt` digraphs, surrogates, `«`/`¿`, `U+2068`) | **JS First-Word / Segment Capitalization Primitive (`ecma402#294`)** (`trailingCase: 'unchanged'` default) |
| **Editorial Title Case** (English AP / Chicago headlines skipping stop words) | Naive `.replace(/\b\w/g, ...)` (`"éClair"`, `"Don'T"`, `"FogãO"`) | **Userland library** composing `Intl.Segmenter` + JS segment primitive (`#294`) |
| **Person names & initials** (`nombre`, `prenom`, `isim`) | `name.split(' ').map(w => w[0].toUpperCase() + w.slice(1).toLowerCase())` | **Do not case-normalize names (`no-change`)**; use **UTS #35 Part 8 (`initialPattern`)** for initials |
