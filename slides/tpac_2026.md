# Capitalization, Titlecasing, and Presentational Case Mapping

## Shane F. Carr (@sffc)
### W3C TPAC 2026 Breakout (#80) — CSSWG × W3C i18n × TC39-TG2

---

## Untangling Terminology: One Word, Six Operations

Standards discussions often stall because **"capitalize"** and **"titlecase"** refer to six distinct operations:

| Term | Precise Meaning | Example (`"español de España"`, `"COVID-19"`) | Web Platform Today |
| :--- | :--- | :--- | :--- |
| **1. Character `Titlecase_Mapping` (`Lt`)** | Maps a single letter/digraph (`ǆ` $\to$ `ǅ`, `ﬁ` $\to$ `Fi`, `nl` `ij` $\to$ `IJ`, Georgian `ka` identity) | `"ǆep"` $\to$ `"ǅep"`, `"თბილისი"` $\to$ `"თბილისი"` | Inside CSS `capitalize`; **unreachable in JS** |
| **2. First-Word / Sentence Case (`titlecase-firstword`)** | Titlecases only the **first word** of a span; preserves trailing case (`TrailingCase::Unchanged`) | `"Español de España"`, `"COVID-19"` | **Missing in CSS (`#8893`) & JS (`#294`)** |
| **3. Start Case (Every-Word Capitalize)** | Titlecases **every word**; preserves trailing case (`U_TITLECASE_NO_LOWERCASE`) | `"Español De España"`, `"COVID-19"` | CSS `text-transform: capitalize` |
| **4. Unicode R3 `toTitlecase(X)`** | Titlecases every word **and lowercases trailing letters** (`TrailingCase::Lower`) | `"Español De España"`, `"Covid-19"`, `"Mcdonald"` | ICU default; Angular `TitleCasePipe`; Python `.title()` |
| **5. Editorial Title Case** | Style-guide rules (AP / Chicago / APA) skipping minor words (`of`, `the`, `de`) | `"The War of the Worlds"` | Userland libraries (style-guide-dependent, `#12526`) |
| **6. Contextual Capitalization (`<contextTransforms>`)** | Applies `titlecase-firstword` or `no-change` based on `Locale × UI Context × Category` | `es` menu: `"Español de España"`; `fr` menu month: `"septembre"` | In CLDR & ICU (`UDisplayContext`); **unexposed in `Intl` (`#355`)** |

---

## Stepping Back: A Two-Phase Pipeline Across Layers

<div class="columns">
<div>

### Phase 1: Contextual & Structural Decision
*Whether* and *which segments* to capitalize:
1. **For CLDR Nouns (`Intl` Formatters):**
   `Locale × UI Context × Category` $\to$ `titlecase-firstword` or `no-change`
   - *Only `Intl` knows the lexical category* (`month` vs. `language` vs. `relative`).
2. **For UI Chrome & Prose (CSS / HTML / App):**
   - **First-word (`sentence`):** Universal across bicameral scripts; Material Design UI.
   - **Every-word (`capitalize`):** English-style chrome (Apple HIG).
   - **Editorial Title Case:** Userland stop-word filtering via `Intl.Segmenter`.

</div>
<div>

### Phase 2: Segment Transform Execution
`Span × Locale` $\to$ **Titlecased Span** *(shared by CSS, `Intl`, & JS)*:
1. **Leading Adjustment (`Auto`):** Advance past `«`, `¿`, quotes, Bidi isolates `U+2068`; keep `"49ers"` & Dutch `"'s-Gravenhage"` intact.
2. **Unicode `Titlecase_Mapping` ($\neq$ `Uppercase`):** Surrogates, NFD combining marks, `ǆ` $\to$ `ǅ`, `ﬁ` $\to$ `Fi`, **Georgian `ka` identity (no-op!)**.
3. **Locale Tailorings:** Dutch `IJ`, Turkish `İ`, Greek initial *tonos* retention, Lithuanian dot removal, Irish `ga` prefixes.
4. **Trailing Case (`Unchanged`):** Preserve `"MacDonald"`, `"iPhone"`, `"España"`, `"COVID-19"`.

</div>
</div>

---

## Why the Web Is Broken Today: Gaps at Every Layer

<div class="columns">
<div>

### What the Platform Provides
- **CSS (`text-transform`):** Only has every-word `capitalize` (and block-only `::first-letter`). No `first-word` / `sentence` (`#8893`). Leaks into screen readers (`accname#239`) & clipboard.
- **HTML (`autocapitalize` & `lang`):** `autocapitalize="none | sentences | words | characters"` only hints mobile keyboards. `<html lang>` is used by CSS, **but ignored by JS `toLocaleUpperCase()`** (which uses OS/browser locale!).
- **JS (`String` & `Intl`):** Only all-caps `toUpperCase()`. **No titlecase primitive (`#294`)** and **no `Intl` `DisplayContext` (`#355`)**.

</div>
<div>

### What Developers Do Instead
- **1.7M+ CSS/TSX/Vue files** apply `text-transform: capitalize` (`every-word` for all locales).
- **100,000+ GitHub files** (and **12,750+ `google3` files**) hardcode:
  ```js
  str.charAt(0).toUpperCase() + str.slice(1)
  ```
- **Stack Overflow #1026069**: **4.7M+ views**, baked into TypeScript `Capitalize<S>`, Vue, MUI, Angular, Closure, and recommended by FormatJS / Moment / date-fns maintainers.

</div>
</div>

# Part 1: The Problem Statement
## How Hardcoded Casing Breaks the Web

## Phase 1 Problem A: CSS `capitalize` Forces Every-Word Casing

In 1,000 CSS/Vue/TSX fragments studied, developers apply `text-transform: capitalize` to translated UI headings, weather descriptions, dates, and language pickers:

<div class="columns">
<div>

```html
<!-- Real patterns in Vue / React / CSS -->
<h2 class="text-capitalize">
  {{ $t('homepage.our_services') }}
</h2>

<span class="capitalize">
  {{ weather.description }}
</span>

<p class="capitalize">
  {{ date.toLocaleDateString('es-ES', opts) }}
</p>

<li style="text-transform: capitalize">
  {{ displayNames.of(locale) }}
</li>
```

</div>
<div>

**Even if `capitalize` skipped prepositions (`de`, `of`), every-word casing is wrong outside English headings:**
- **French heading:** `"nos services numériques"` $\to$ ❌ **`"Nos Services Numériques"`** *(wants `"Nos services numériques"`)*
- **Spanish/French weather (1,908 files):** `"cielo claro"` $\to$ ❌ **`"Cielo Claro"`**; `"ciel dégagé"` $\to$ ❌ **`"Ciel Dégagé"`**
- **Dates (FullCalendar, Vue/TSX):** `"lunes, 12 de enero"` $\to$ ❌ **`"Lunes, 12 De Enero"`**; `"сентябрь 2026 г."` $\to$ ❌ **`"Сентябрь 2026 Г."`**
- **Language pickers (Svelte/Vue & `immich`):** `"español de España"` $\to$ ❌ **`"Español De España"`**; `"norsk bokmål"` $\to$ ❌ **`"Norsk Bokmål"`**

</div>
</div>

## Phase 1 Problem B: Unconditional JS First-Word Casing Ignores `<contextTransforms>`

Developers who notice CSS `capitalize` hits every word switch to JS (as Spanish devs noted in comments: *"Con `capitalize` de CSS quedaba 'Septiembre De 2026'"*) and hardcode **`titlecase-firstword` for every locale and UI slot**:

```js
// Found across dozens of GitHub calendar, datepicker, and i18n utilities:
function formatMonthLabel(date, locale) {
  const s = date.toLocaleDateString(locale, { month: 'long', year: 'numeric' });
  return s.charAt(0).toUpperCase() + s.slice(1); // ❌ Runs for EVERY locale & UI context!
}
```

**Why neither CSS nor unconditional JS can make the Phase 1 decision for CLDR nouns:**

| Item & UI Context | Spanish (`es`) | French (`fr`) | Czech (`cs`) | Swedish (`sv`) / Finnish (`fi`) |
| :--- | :---: | :---: | :---: | :---: |
| **Month in Calendar Header (`stand-alone`)** | `Septiembre` (Cap) | `Septembre` (Cap) | **`září` (`no-change`)** | **`september` / `syyskuu` (`no-change`)** |
| **Month in `<select>` Menu (`uiListOrMenu`)** | `Septiembre` (Cap) | **`septembre` (`no-change`)** | `Září` (Cap) | **`september` / `syyskuu` (`no-change`)** |
| **Language in `<select>` Menu (`uiListOrMenu`)** | `Español` (Cap) | `Français` (Cap) | `Čeština` (Cap) | `Svenska` / `Suomi` (Cap) |
| **Language Standalone (`stand-alone`)** | `Español` (Cap) | **`français` (`no-change`)** | `Čeština` (Cap) | `Svenska` / **`suomi` (`no-change`)** |
| **In Running Text (`middle-of-sentence`)** | **`septiembre`** | **`septembre`** | **`září`** | **`september` / `syyskuu`** |

## Phase 1 Problem C: `Intl` Leaves Browsers & Locales Inconsistent Today

CLDR stores terms in **middle-of-sentence** form (`"enero"`, `"janvier"`, `"español"`, `"русский"`) and uses `<contextTransforms>` for UI contexts. Because `ECMA-402` has not exposed context (`ecma402#355`):

<div class="columns">
<div>

### 1. Cross-Browser Divergence in `Intl.DisplayNames`
- **V8 (Chrome):** passes `UDISPCTX_CAPITALIZATION_NONE`
- **SpiderMonkey (Firefox) & JSC (Safari):** pass `UDISPCTX_CAPITALIZATION_FOR_STANDALONE`

```js
new Intl.DisplayNames(['es'], { type: 'language' })
  .of('es');
// Chrome:         "español" (lowercase)
// Firefox/Safari: "Español" (Capitalized)

new Intl.DisplayNames(['fr'], { type: 'language' })
  .of('fr');
// ALL browsers:   "français" (lowercase!)
// Why? CLDR 'fr' (and 'fi', 'da') only capitalizes
// languages in uiListOrMenu, not stand-alone!
```

</div>
<div>

### 2. Real-World Pain in Production UIs
- **Perplexity Language Picker (`ecma402#355`):**
  Across ~50 interface languages in Chrome, `Intl.DisplayNames` returns **27 lowercase** (`"español"`, `"français"`, `"русский"`, `"polski"`, `"čeština"`, `"suomi"`) and **~23 capitalized** (`"English"`, `"Deutsch"`, `"Nederlands"`, `"Türkçe"`).
- **Project Fluent (`fluent#299`) & FormatJS (`#1527`):**
  Maintainers declined to add custom casing filters, pointing to `ecma402#355` as the missing platform primitive.

</div>
</div>

## Phase 1 Problem D: Why `.slice(1).toLowerCase()` & Name Normalization Fail

In 2,000+ lines of multilingual GitHub call sites studied (`nombre`, `prenom`, `nome`, `isim`, `imie`), **person names** are the *only* category where developers routinely lowercase the tail (0% of weather, error, month, or weekday sites lowercase the tail!):

```js
// Mongoose pre-save hooks, Express handlers, Discord bots on GitHub:
const normalizeName = s => s.charAt(0).toUpperCase() + s.slice(1).toLowerCase();
const titleName = s => s.toLowerCase().split(' ').map(normalizeName).join(' ');
```

- **Compound & hyphenated names:** `"maría josé"` $\to$ ❌ **`"María josé"`**; `"jean-pierre"` $\to$ ❌ **`"Jean-pierre"`**
- **Particles & internal caps:** `"DE LA CRUZ"` $\to$ ❌ **`"De La Cruz"`**; `"van der Berg"` $\to$ ❌ **`"Van Der Berg"`**; `"McDonald"` $\to$ ❌ **`"Mcdonald"`**; `"O'Connor"` $\to$ ❌ **`"O'connor"`**; Dutch `"'t Hooft"` $\to$ ❌ **`"'t hooft"`**
- **Turkish & acronyms:** Turkish `"IŞIK"` $\to$ ❌ **`"Işik"`**; `"ilayda"` $\to$ ❌ **`"Ilayda"`** (needs `"İlayda"`); Angular `TitleCasePipe` turns `"COVID-19"` $\to$ ❌ **`"Covid-19"`** (`angular#41420`)
- **Two lessons:** (1) Never case-normalize person names (`no-change`; use UTS #35 Part 8 `initialPattern` for initials); (2) **Default `trailingCase` in JS must be `'unchanged'`**!

## Phase 2 Problem A: `str[0].toUpperCase()` Is Not Titlecase

Even when `titlecase-firstword` *is* the right choice, `str[0].toUpperCase() + str.slice(1)` applies **`Uppercase_Mapping` to UTF-16 code unit 0** instead of **`Titlecase_Mapping` to the first segment**:

| Script / Rule | Input | `str[0].toUpperCase() + str.slice(1)` | Correct Titlecase | Why It Fails (Verified Live in V8) |
| :--- | :--- | :--- | :--- | :--- |
| **Georgian (`ka`)** | `"თბილისი"` (*Tbilisi*)<br>`"იანვარი"` (*January*) | ❌ **`"Თბილისი"`**<br>❌ **`"Იანვარი"`** | **`"თბილისი"`**<br>**`"იანვარი"`** | Georgian has no word capitalization (`Titlecase_Mapping` = self; *Mtavruli* `Თ` is strictly ALL-CAPS!) |
| **Dutch `ij` (`nl`)** | `"ijsland"` (*Iceland*) | ❌ **`"Ijsland"`** *(even with `toLocaleUpperCase('nl')`!)* | **`"IJsland"`** | `str[0]` only passes `"i"`, hiding the `"ij"` digraph from the case mapper |
| **Serbo-Croatian (`Lt`)** | `"ǆep"` (*pocket*) | ❌ **`"Ǆep"`** (`DŽep`) | **`"ǅep"`** (`Džep`) | `U+01C6` maps to `Lt` `ǅ` (`U+01C5`), not `Lu` `Ǆ` (`U+01C4`) |
| **Ligatures & Armenian** | `"ﬁrst"`, `"ևս"` | ❌ **`"FIrst"`**, **`"ԵՒս"`** | **`"First"`**, **`"Եւս"`** | `SpecialCasing.txt` upper (`FI`, `ԵՒ`) $\neq$ title (`Fi`, `Եւ`) |
| **Greek Polytonic (`Lt`)** | `"ᾳδης"` (*Hades*) | ❌ **`"ΑΙδης"`** | **`"ᾼδης"`** | Upper expands *ypogegrammeni* to two capitals (`ΑΙ`); title uses *prosgegrammeni* (`ᾼ`) |
| **Turkish (`tr` / `az`)** | `"istanbul"` | ❌ **`"Istanbul"`** | **`"İstanbul"`** | `.toUpperCase()` is locale-blind, and `.toLocaleUpperCase()` ignores `<html lang="tr">`! |

## Phase 2 Problem B: Surrogates, Combining Marks, Leading Adjustment, & `\b\w`

<div class="columns">
<div>

### 1. UTF-16 Surrogates (9 Bicameral Scripts)
- In **Adlam** (`"𞤢𞤤𞤢𞤲𞤣"` *Sunday*), **Deseret**, **Osage**, etc., `str[0]` is a lone high surrogate (`\uD83A`).
- `"\uD83A".toUpperCase()` is a **silent no-op** (`camelcase#117`)!
- `<span>{str[0].toUpperCase()}</span>{str.slice(1)}` tears surrogates across DOM nodes into **`U+FFFD U+FFFD`**.

### 2. Leading Punctuation, Bidi, & Elisions
- Spanish `"¿cómo estás?"`, French `"«bonjour»"`, and **Fluent** Bidi isolates (`"\u2068lundi\u2069"`) have a non-letter at `str[0]` — **nothing is capitalized**!
- Conversely, naive "skip to first cased letter" (`ToCased`) turns `"49ers"` $\to$ ❌ **`"49Ers"`** and Dutch `"'s-Gravenhage"` $\to$ ❌ **`"'S-Gravenhage"`**.

</div>
<div>

### 3. Lithuanian (`lt`) & NFD Combining Marks
- Slicing `str[0]` away from `str.slice(1)` on Lithuanian `"i\u0307\u0303"` hides `\u0307` from `toLocaleUpperCase('lt')`, leaving a double-dotted **`"I\u0307\u0303"`**; DOM-splitting NFD `"e\u0301cole"` renders a detached dotted circle **`E◌́cole`**.

### 4. ASCII-Only RegExp `\b\w` (`Angular #23267`)
```js
str.replace(/\b\w/g, c => c.toUpperCase())
```
- `\b` and `\w` are **strictly ASCII** (even with `/u`):
  - `"éclair"` $\to$ ❌ **`"éClair"`**; `"février"` $\to$ ❌ **`"FéVrier"`**
  - `"FOGÃO"` $\to$ ❌ **`"FogãO"`**; `"don't"` $\to$ ❌ **`"Don'T"`**
  - Catalan `"cancel·lar"` $\to$ ❌ **`"Cancel·Lar"`**

</div>
</div>

## Phase 2 Problem C: Why CSS `::first-letter` & Leaks Don't Save Us

<div class="columns">
<div>

### Why `.label::first-letter` Fails
```css
.label::first-letter {
  text-transform: uppercase; /* or capitalize */
}
```
1. **Ignored on inline elements (`<span>`, `<a>`, `<label>`):** Only applies to block containers (`CSS Pseudo-Elements 4 §2.2`), forcing `display: inline-block` layout hacks (`SO #3961725`).
2. **Greek (`lang="el"`) *tonos* & Georgian (`ka`) bug with `uppercase`:** Tutorials prescribe `text-transform: uppercase`, which strips Greek initial *tonos* (`"Άνθρωπος"` $\to$ ❌ **`"Ανθρωπος"`**) and applies Georgian Mtavruli (`"Თბილისი"`).
3. **Even `::first-letter { text-transform: capitalize }` fails** on inline boxes, Dutch `IJ` in Blink (`"Ijsland"`, `crbug.com/1172333`), and `«\u00A0Bonjour` (`crbug.com/41270370`).

</div>
<div>

### Leaks & Unreachable Sinks
- **Screen readers (`w3c/accname#239`, `csswg#10732`):**
  `<button style="text-transform: uppercase">Call us</button>` exposes transformed text to the Accessibility Tree and is announced as **"Call U.S."**
- **Clipboard & `innerText` (`webkit.org/b/43202`):**
  Safari still copies visually transformed text to the clipboard (Chrome fixed in v127); `innerText` mutates it by spec in all browsers.
- **Unreachable non-CSS sinks:**
  - `<title>` (`document.title`)
  - `<option>` (OS-native select popups)
  - `aria-label`, `alt`, `title` attributes
  - `<canvas>`, `new Notification()`

</div>
</div>

# Part 2: Empirical Evidence & Platform Design Space
## Aligning CSS, `Intl`, and JavaScript Around the Two Phases

---

## What Are Developers Actually Capitalizing? (GitHub Study)

Across **563 classified JS hits** (400 real call sites) + **~190 localized `Intl` call sites** + **1,000 CSS `.capitalize` fragments** + **2,000+ multilingual human-text lines**:

| What Is Being Capitalized | Share of JS Sample (+ CSS Usage) | What Phase 1 & Phase 2 Operation They Actually Need |
| :--- | :---: | :--- |
| **Internal keys/enums/statuses $\to$ UI labels, chips, tabs, headers, & translated strings (`$t('files')`)** | **51% of JS hits**<br>*(+ 33% of Vue `$t()` `.capitalize`)* | **First-Word Transform (`titlecase-firstword`)** in CSS (`text-transform: first-word`) or JS (`trailingCase: 'unchanged'`) |
| **API/DB phrases (`weather[0].description`), Go/Rust `error.message` toasts, transcripts, MF2** | **14.5% of JS hits**<br>*(1,908 weather + 106 error files; 0% lower tail!)* | **JS First-Word / Segment Primitive (`#294`)** with `leadingAdjustment: 'auto'` & `trailingCase: 'unchanged'` |
| **`Intl` / date-library outputs (`DateTimeFormat`, `DisplayNames`, `RelativeTimeFormat`)** | **~1% random JS**<br>*(~10–15% TS file ceiling + ~25–30% of CSS date/calendar hits)* | **CLDR `<contextTransforms>` (`#355`)** (`standalone`, `ui-list-or-menu`, `beginning-of-sentence`, `middle-of-sentence`) + **CLDR data audit** |
| **Person & place names (`nombre`, `prenom`, `isim`)** | **6.5% of JS hits**<br>*(only group using `.toLowerCase()`!)* | **`no-change`** (do not case-normalize names; use UTS #35 Part 8 `initialPattern` for initials) |
| **Code / identifier generation (`PascalCase`, `on${Key}`)** | **26% of JS hits** | ASCII `s[0].toUpperCase() + s.slice(1)` *(locale-insensitive, already works)* |

> **Key Takeaway:** Neither `Intl` (`#355`), nor CSS (`#8893`), nor a JS primitive (`#294`) can solve this alone—each covers a distinct slice of the Web, and all three share the **same Phase 2 execution**.

## How CLDR, ICU4C, and ICU4X Model the Two Phases

<div class="columns">
<div>

### Phase 1: CLDR `<contextTransforms>` (UTS #35)
- Stores strings in `middle-of-sentence` form (capitalizing is lossless; lowercasing `"Español de España"` corrupts `"España"`).
- Maps `(locale, usage_category) × (uiListOrMenu | stand-alone | beginning-of-sentence)` $\to$ `titlecase-firstword` or `no-change`.
- **Tiny data footprint:** Compiled in ICU to a 2-element vector `{ uiListOrMenu, standAlone }` per usage category (a few flags per locale, not megabytes of grammar data!).

</div>
<div>

### Phase 2: `ICU4X TitlecaseMapper` / `ICU4C`
- `TitlecaseMapper::titlecase_segment` (`ICU4X`) / `U_TITLECASE_WHOLE_STRING` (`ICU4C`) executes on a single span with:
  - **`TrailingCase::Unchanged`** (`U_TITLECASE_NO_LOWERCASE`)
  - **`LeadingAdjustment::Auto`** (skips `«`, `¿`, `U+2068`; keeps `"49ers"` and Dutch `"'s-Gravenhage"` / `"'t Hooft"` intact)
  - Full `Titlecase_Mapping` + `nl`/`tr`/`el`/`lt`/`hy`/`ka` tailoring.
- **Zero word-segmenter (`BreakIterator`) cost** when applied to a single segment or the first word of a string!

</div>
</div>

## Solution Track 1: CSS (`css-text`) & Accessibility Alignment

<div class="columns">
<div>

### 1. Standardize `text-transform: first-word` / `sentence` (`csswg-drafts#8893`)
- Direct declarative primitive for `titlecase-firstword`:
  - Applies Unicode `Titlecase_Mapping` + `TrailingCase::Unchanged` + `LeadingAdjustment::Auto` to the first word of an element.
  - **Works on inline elements (`<span>`, `<a>`, `<label>`)** as well as blocks — eliminating `display: inline-block` `::first-letter` hacks and Greek *tonos* / Georgian *Mtavruli* bugs.
  - Replaces `.capitalize` on UI headings, chips, badges, and translated strings (`"Nos services numériques"`).
- *What about editorial Title Case (`#12526`)?* Stop words (`of`, `the`) are style-guide-specific (AP vs. Chicago); leave to userland or custom `@text-transform` (`#3132`).

</div>
<div>

### 2. Fix Tailoring Interop, Perf, & Leaks
- **Shared segment fast-path:** Avoid Blink's 4.3% Speedometer 3 regression (`crbug.com/420998400` when shipping Dutch `IJ` in `crbug.com/41248541`) by caching `BreakIterator` for `capitalize` and using zero-breaker segment titlecasing for `first-word`.
- **Language tailorings & word boundaries:** Align engines on Dutch `IJ`, Irish `ga` prefix mutations (`an t-uisce` $\to$ `AN tUISCE`, currently Gecko-only), and UAX #29 word boundaries (`foo.bar`, `cancel·lar`).
- **Fix Accessibility & Clipboard Leaks:** Do not expose visual `text-transform` mutations to `accname` (`w3c/accname#239`) or Safari plain-text clipboard (`webkit.org/b/43202`).

</div>
</div>

## Solution Track 2: Contextual Capitalization in `Intl` (`tc39/ecma402#355`)

<div class="columns">
<div>

### 1. Expose `capitalization` Option in `Intl`
For CLDR nouns (`DateTimeFormat`, `DisplayNames`, `RelativeTimeFormat`), **only `Intl` knows the lexical category**:

```js
// Standalone calendar header:
new Intl.DateTimeFormat(locale, {
  month: 'long', year: 'numeric',
  capitalization: 'standalone',
  // 'middle-of-sentence' (default) | 'beginning-of-sentence'
  // | 'ui-list-or-menu' | 'standalone'
}).format(date);
// es -> "Septiembre de 2026"
// sv -> "september 2026" (respects Swedish no-change!)

// Language picker menu:
new Intl.DisplayNames([locale], {
  type: 'language',
  capitalization: 'ui-list-or-menu',
}).of('es-ES');
// fr -> "Espagnol d’Espagne" (vs "espagnol d’Espagne")
```
- Resolves Chrome vs. Firefox/Safari `Intl.DisplayNames` divergence by specifying `'middle-of-sentence'` as the default.

</div>
<div>

### 2. Co-Requisite: CLDR & ICU Data Audit
Our GitHub call-site audit revealed missing CLDR `<contextTransforms>` flags where native speakers expect capitalization:
1. **Portuguese (`pt`) months:** #1 locale in our GitHub study (27 `pt-BR` sites capitalizing `"Setembro de 2026"`), yet `pt.xml` has `days` and `relative` **but is missing `month-*`**!
2. **Language pickers (`languages`):** Missing `uiListOrMenu` in **`pl` (`polski`), `hu` (`magyar`), `ca` (`català`), `ro` (`română`), `bg` (`български`), `sr`, `sl`, `lt`, `lv`, `et`, `is`** (half of Perplexity's 27 lowercase languages!).
3. **Relative dates (`relative`):** Missing in **`fr` (`hier`), `es` (`ayer`), `it` (`ieri`)**; and ICU4C `RelativeDateTimeFormatter` (`reldatefmt.cpp:816`) currently ignores `STANDALONE` & `UI_LIST_OR_MENU`!

## Solution Track 3: JS Case Mapping Building Block (`tc39/ecma402#294`)

How do we fix the **90%+ of JS call sites** that transform non-`Intl` strings (weather/API text, error toasts, `<title>`, `<option>`, `aria-label`, MF2 messages) while addressing all TG2 vendor objections?

<div class="columns">
<div>

### Single-Span Primitive + `Intl.Segmenter`
```js
// 1. Direct replacement for s[0].toUpperCase() + s.slice(1)
// (Default: trailingCase: 'unchanged', leadingAdjustment: 'auto')
str.toLocaleCapitalize(locale);
// "cielo claro" ('es')     -> "Cielo claro"
// "«bonjour»" ('fr')       -> "«Bonjour»"
// "\u2068lundi\u2069"      -> "\u2068Lundi\u2069"
// "ijsland" ('nl')         -> "IJsland"
// "'s-Gravenhage" ('nl')   -> "'s-Gravenhage"
// "თბილისი" ('ka')         -> "თბილისი" (no-op!)
// "ǆep" ('hr')             -> "ǅep"

// 2. Composes with Intl.Segmenter for 1KB userland Title Case:
const segs = new Intl.Segmenter(locale, { granularity: 'word' });
let out = '';
for (const { segment, isWordLike } of segs.segment(str)) {
  out += isWordLike && !STOP.has(segment.toLocaleLowerCase(locale))
    ? segment.toLocaleCapitalize(locale, { trailingCase: 'lower' })
    : segment;
}
```

</div>
<div>

### Resolves All 4 TG2 Vendor Objections
1. **Why not CSS-only?** Non-CSS sinks (`<title>`, `<option>`, `aria-label`, `<canvas>`, `Notification`), MF2 functions (`message-format-wg#38`), and avoiding `accname`/clipboard leaks.
2. **`MacDonald` & `iPhone` preserved:** Default `trailingCase: 'unchanged'` never lowercases `"MacDonald"`, `"iPhone"`, `"COVID-19"`, or `"España"`.
3. **Zero `BreakIterator` regression:** Single-span default (`U_TITLECASE_WHOLE_STRING` / `ICU4X titlecase_segment`) requires **no word segmenter**, avoiding Blink's 4.3% Speedometer 3 regression.
4. **Stop words stay in userland:** Style-guide rules (AP vs. Chicago) don't bloat browser engines; method name avoids the overloaded term `"titleCase"`.

## Summary: Matching Each Use Case to the Right Tool

| Real-World Use Case (from GitHub Study) | Broken Code Today | Proposed Platform Solution |
| :--- | :--- | :--- |
| **Declarative UI headings, chips, badges, inline `<span>`s, translated labels** (`$t('...')`, status labels) | `text-transform: capitalize` (forces every-word casing onto `fr`/`es`/`no`) or block-only `::first-letter` | **CSS `text-transform: first-word` / `sentence` (`#8893`)** + engine tailoring & `accname` fixes |
| **`Intl` dates, months, weekdays, languages, relative time in headers & menus** | `cap(date.toLocaleDateString(...))` or CSS `.capitalize` (ignores `sv`/`fr`/`cs` `no-change` rules) | **`Intl` `{ capitalization: 'standalone' \| 'ui-list-or-menu' \| ... }` (`ecma402#355`)** + CLDR `<contextTransforms>` audit |
| **Non-`Intl` strings in JS: toasts, API phrases (`weather.description`), MF2, `<title>`, `<option>`, `aria-label`** | `s.charAt(0).toUpperCase() + s.slice(1)` (breaks `ka`, `nl` `IJ`/`'s-`, `tr` `İ`, `Lt` digraphs, surrogates, `«`/`¿`, `U+2068`) | **JS First-Word / Segment Capitalization Primitive (`ecma402#294`)** (`trailingCase: 'unchanged'` default) |
| **Editorial Title Case** (English AP / Chicago headlines skipping stop words) | Naive `.replace(/\b\w/g, ...)` (`"éClair"`, `"Don'T"`, `"FogãO"`) | **Userland library** composing `Intl.Segmenter` + JS segment primitive (`#294`) |
| **Person names & initials** (`nombre`, `prenom`, `isim`) | `name.split(' ').map(w => w[0].toUpperCase() + w.slice(1).toLowerCase())` | **Do not case-normalize names (`no-change`)**; use **UTS #35 Part 8 (`initialPattern`)** for initials |
