# Capitalization, Titlecasing, and Presentational Case Mapping

## Shane F. Carr (@sffc)
### W3C TPAC 2026 Breakout (#80) — CSSWG × W3C i18n × TC39-TG2

---

## Stepping Back: Capitalization Is a Two-Phase Pipeline

To display text with the right casing in a UI, two distinct steps must happen:

<div class="columns">
<div>

### Phase 1: Contextual Decision
`Locale × UI Context × Category` $\to$ **Mode**

What does the locale's orthography require in this UI slot?
- **`titlecase-words`**: Capitalize every major word *(e.g. English headings)*
- **`titlecase-firstword`**: Capitalize only the first word *(e.g. French/Spanish headings, standalone labels, sentence starts)*
- **`no-change`**: Leave the text alone *(e.g. Swedish standalone months, French menu months, Georgian, person names)*

</div>
<div>

### Phase 2: Transform Execution
`Mode × Locale × Text` $\to$ **Cased String**

Apply the chosen mode to the text:
- Advance past leading punctuation (`«`, `¿`, Bidi isolates `U+2068`)
- Apply Unicode `Titlecase_Mapping` ($\neq$ `Uppercase_Mapping`)
- Apply locale character tailorings (`nl` `IJ`, `tr` `İ`, `el` accents, `ka` identity)
- Preserve trailing case (`MacDonald`, `iPhone`, `España`)

</div>
</div>

---

## Why the Web Is Broken Today: A Void at Both Phases

<div class="columns">
<div>

### What the Platform Provides
- **Phase 1 (Contextual Decision):** **Nothing.** Neither CSS, HTML, nor `Intl` selects a transform based on locale + UI context.
- **Phase 2 (Execution):** **Half a primitive.**
  - CSS only has every-word `capitalize` (and block-only `::first-letter`).
  - JS only has all-caps `toUpperCase()` / `toLocaleUpperCase()` — **no titlecase mapping at all**.

</div>
<div>

### What Developers Do Instead
- **1.7M+ CSS/TSX/Vue files** hardcode `text-transform: capitalize` (`titlecase-words` for all locales).
- **100,000+ GitHub files** (and **12,750+ `google3` files**) hardcode:
  ```js
  str.charAt(0).toUpperCase() + str.slice(1)
  ```
- **Stack Overflow #1026069**: **4.7M+ views**, baked into TypeScript `Capitalize<S>`, Vue, MUI, Angular, Closure.

</div>
</div>

# Part 1: The Problem Statement
## How Hardcoded Casing Breaks the Web

---

## Phase 1 Problem A: Is `text-transform: capitalize` the Right Tool?

Suppose `text-transform: capitalize` is fixed to skip stop words (`of`, `the`, `de`). **Is it the right tool for headings, UI labels, and descriptions?**

<div class="columns">
<div>

```html
<!-- Real patterns in Vue / React / CSS -->
<h2 class="text-capitalize">
  {{ $t('homepage.our_services') }}
</h2>

<span class="capitalize">
  {{ weather.description }}
</span>

<li style="text-transform: capitalize">
  {{ displayNames.of(locale) }}
</li>
```

</div>
<div>

**No — it forces English Title Case (`titlecase-words`) onto every language:**
- **French heading:** `"nos services numériques"` $\to$ ❌ **`"Nos Services Numériques"`** *(wants `"Nos services numériques"`)*
- **Spanish/French weather (1,908 files):** `"cielo claro"` $\to$ ❌ **`"Cielo Claro"`**; `"ciel dégagé"` $\to$ ❌ **`"Ciel Dégagé"`**
- **Language picker (`immich`, 70k⭐):** `"norsk bokmål"` $\to$ ❌ **`"Norsk Bokmål"`**; `"srpski (latinica)"` $\to$ ❌ **`"Srpski (Latinica)"`**
- **Full dates:** `"lundi 12 janvier"` $\to$ ❌ **`"Lundi 12 Janvier"`**

</div>
</div>

---

## Phase 1 Problem B: When the Right Transform Is `no-change`

Developers who notice CSS `capitalize` hits every word switch to JS and hardcode **`titlecase-firstword` for every locale and UI slot**:

```js
// Found across dozens of GitHub calendar, datepicker, and i18n utilities:
function formatMonthLabel(date, locale) {
  const s = date.toLocaleDateString(locale, { month: 'long' });
  return s.charAt(0).toUpperCase() + s.slice(1); // ❌ Runs for EVERY locale & UI context!
}
```

**Why unconditional first-word capitalization is ALSO wrong (CLDR `<contextTransforms>`):**

| Item & UI Context | Spanish (`es`) | French (`fr`) | Czech (`cs`) | Swedish (`sv`) / Finnish (`fi`) |
| :--- | :---: | :---: | :---: | :---: |
| **Month in Calendar Header (`stand-alone`)** | `Septiembre` (Cap) | `Septembre` (Cap) | **`září` (`no-change`)** | **`september` / `syyskuu` (`no-change`)** |
| **Month in `<select>` Menu (`uiListOrMenu`)** | `Septiembre` (Cap) | **`septembre` (`no-change`)** | `Září` (Cap) | **`september` / `syyskuu` (`no-change`)** |
| **Language in `<select>` Menu (`uiListOrMenu`)** | `Español` (Cap) | `Français` (Cap) | `Čeština` (Cap) | `Svenska` / `Suomi` (Cap) |
| **Language Standalone (`stand-alone`)** | `Español` (Cap) | **`français` (`no-change`)** | `Čeština` (Cap) | `Svenska` / **`suomi` (`no-change`)** |
| **In Running Text (`middle-of-sentence`)** | **`septiembre`** | **`septembre`** | **`září`** | **`september` / `syyskuu`** |

## Phase 1 Problem C: `Intl` Leaves Browsers & Locales Inconsistent Today

CLDR stores terms in **middle-of-sentence** form (`"enero"`, `"janvier"`, `"español"`) and uses `<contextTransforms>` for UI contexts. Because `ECMA-402` has not exposed context (`ecma402#355`):

<div class="columns">
<div>

### 1. Cross-Browser Divergence in `Intl.DisplayNames`
- **V8 (Chrome):** passes `CAPITALIZATION_NONE`
- **SpiderMonkey (Firefox) & JSC (Safari):** pass `CAPITALIZATION_FOR_STANDALONE`

```js
new Intl.DisplayNames(['es'], { type: 'language' })
  .of('es');
// Chrome:         "español"
// Firefox/Safari: "Español"

new Intl.DisplayNames(['fr'], { type: 'language' })
  .of('fr');
// All browsers:   "français"
// (CLDR 'fr' only capitalizes in uiListOrMenu!)
```

</div>
<div>

### 2. Cross-Locale Divergence in `Intl.DateTimeFormat`
- Russian XML baked capital `"Январь"` into `<monthContext type="stand-alone">`, while Spanish/French stored `"enero"` / `"janvier"` lowercase expecting `<contextTransforms>`.

```js
new Intl.DateTimeFormat('ru', { month: 'long' })
  .format(date); // "Январь" (Capitalized)

new Intl.DateTimeFormat('es', { month: 'long' })
  .format(date); // "enero"  (Lowercase)
```

</div>
</div>

## Phase 1 Problem D: Person Names Should Not Be Re-Cased at All

In 2,000+ lines of multilingual GitHub call sites studied (`nombre`, `prenom`, `nome`, `isim`, `imie`), **person names** are the only category where developers routinely lowercase the tail:

```js
// Mongoose pre-save hooks, Express handlers, Discord bots on GitHub:
const normalizeName = s => s.charAt(0).toUpperCase() + s.slice(1).toLowerCase();
const titleName = s => s.toLowerCase().split(' ').map(normalizeName).join(' ');
```

- **Compound given names:** `"maría josé"` $\to$ ❌ **`"María josé"`**; `"jean-pierre"` $\to$ ❌ **`"Jean-pierre"`**
- **Particles & internal caps:** `"DE LA CRUZ"` $\to$ ❌ **`"De La Cruz"`**; `"van der Berg"` $\to$ ❌ **`"Van Der Berg"`**; `"McDonald"` $\to$ ❌ **`"Mcdonald"`**; `"O'Connor"` $\to$ ❌ **`"O'connor"`**
- **Locale-specific orthography:** Turkish `"IŞIK"` $\to$ ❌ **`"Işik"`**; `"ilayda"` $\to$ ❌ **`"Ilayda"`** (needs `"İlayda"`); Dutch `"'t Hooft"` $\to$ ❌ **`"'T Hooft"`**
- **The Phase 1 lesson:** For person names, the right transform mode is **`no-change`**.

## Phase 2 Problem A: `str[0].toUpperCase()` Is Not Titlecase

Even when `titlecase-firstword` *is* the right Phase 1 choice, `str[0].toUpperCase() + str.slice(1)` applies **`Uppercase_Mapping` to code unit 0** instead of **`Titlecase_Mapping` to the first segment**:

| Script / Case | Input | `str[0].toUpperCase() + str.slice(1)` | Correct Titlecase | Why It Fails |
| :--- | :--- | :--- | :--- | :--- |
| **Georgian (`ka`)** | `"თბილისი"` (*Tbilisi*)<br>`"იანვარი"` (*January*) | ❌ **`"Თბილისი"`**<br>❌ **`"Იანვარი"`** | **`"თბილისი"`**<br>**`"იანვარი"`** | Georgian has no word capitalization (`Titlecase_Mapping` = self; *Mtavruli* `Თ` is strictly ALL-CAPS!) |
| **Dutch `ij` (`nl`)** | `"ijsland"` (*Iceland*) | ❌ **`"Ijsland"`** *(even with `toLocaleUpperCase('nl')`!)* | **`"IJsland"`** | `str[0]` only passes `"i"`, hiding the `"ij"` digraph from the case mapper |
| **Dutch Elisions** | `"'s-Gravenhage"` | ❌ **`"'S-Gravenhage"`** *(when skipping `'`)* | **`"'s-Gravenhage"`** | Archaic `'s` / `'t` article prefix must stay lowercase |
| **Croatian / Serbian** | `"ǆep"` (*pocket*) | ❌ **`"Ǆep"`** (`DZep`) | **`"ǅep"`** (`Dzep`) | `U+01C6` maps to `Lt` `ǅ` (`U+01C5`), not `Lu` `Ǆ` |
| **Ligatures & Armenian** | `"ﬁrst"`, `"ևս"` | ❌ **`"FIrst"`**, **`"ԵՒս"`** | **`"First"`**, **`"Եւս"`** | `SpecialCasing.txt` upper (`FI`, `ԵՒ`) $\neq$ title (`Fi`, `Եւ`) |
| **Turkish (`tr` / `az`)** | `"istanbul"` | ❌ **`"Istanbul"`** | **`"İstanbul"`** | `.toUpperCase()` is locale-insensitive |

## Phase 2 Problem B: Surrogates, Combining Marks, Punctuation, & `\b\w`

<div class="columns">
<div>

### 1. UTF-16 Surrogates (9 Bicameral Scripts)
- In **Adlam** (`"𞤢𞤤𞤢𞤲𞤣"` *Sunday*), **Deseret**, **Osage**, etc., `str[0]` is a lone high surrogate (`\uD83A`).
- `"\uD83A".toUpperCase()` is a **silent no-op**!
- `<span>{str[0].toUpperCase()}</span>{str.slice(1)}` tears surrogates across DOM nodes into **`U+FFFD U+FFFD`**.

### 2. Leading Punctuation & Bidi Isolates
- Spanish `"¿cómo estás?"`, French `"«bonjour»"`, and **Project Fluent** Bidi isolates (`"\u2068lundi\u2069"`) have a non-letter at `str[0]` — **nothing is capitalized**!

</div>
<div>

### 3. Lithuanian (`lt`) & NFD Combining Marks
- Slicing `str[0]` away from `str.slice(1)` on Lithuanian `"i\u0307\u0303"` hides `\u0307` from `toLocaleUpperCase('lt')`, leaving a double-dotted **`"I\u0307\u0303"`**.

### 4. ASCII-Only RegExp `\b\w` (`Angular #23267`)
```js
str.replace(/\b\w/g, c => c.toUpperCase())
```
- `\b` and `\w` are **strictly ASCII** (even with `/u`):
  - `"éclair"` $\to$ ❌ **`"éClair"`**
  - `"février"` $\to$ ❌ **`"FéVrier"`**
  - `"FOGÃO"` $\to$ ❌ **`"FogãO"`**
  - Catalan `"cancel·lar"` $\to$ ❌ **`"Cancel·Lar"`**

</div>
</div>

---

## Phase 2 Problem C: Why CSS `::first-letter` & Leaks Don't Save Us

<div class="columns">
<div>

### Why `.label::first-letter` Fails
```css
.label::first-letter {
  text-transform: uppercase;
}
```
1. **Ignored on inline elements (`<span>`, `<a>`, `<label>`):** Only applies to block containers (`CSS Pseudo-Elements 4 §2.2`), forcing `display: inline-block` layout hacks.
2. **Greek (`lang="el"`) *tonos* bug:** In Greek, all-caps `uppercase` strips *tonos* accents (`"ΑΝΘΡΩΠΟΣ"`), whereas initial `titlecase` **must retain the *tonos*** (`"Άνθρωπος"`). `uppercase` on `::first-letter` produces ❌ **`"Ανθρωπος"`**!
3. **Fails on Dutch `IJ` in Blink (`"Ijsland"`) and French guillemets (`«\u00A0Bonjour`).**

</div>
<div>

### Leaks & Unreachable Sinks
- **Screen readers (`w3c/accname#239`):**
  `<button style="text-transform: uppercase">Call us</button>` is announced as **"Call U.S."**
- **Clipboard (`webkit.org/b/43202`):**
  Safari copies visually transformed text to the clipboard; `innerText` mutates it in all browsers.
- **Unreachable non-CSS sinks:**
  - `<title>` (`document.title`)
  - `<option>` (OS-native select popups)
  - `aria-label`, `alt`, `title` attributes
  - `<canvas>`, `new Notification()`

</div>
</div>

# Part 2: Empirical Evidence & Platform Design Space
## Designing CSS and JavaScript Around the Two Phases

---

## What Are the Call Sites Actually Capitalizing? (GitHub Study)

Hand-classified sample of **563 GitHub hits** (400 real call sites) + 1,000 targeted CSS & formatter fragments:

| What Is Being Capitalized | Share of Real JS Call Sites | What Phase 1 & Phase 2 Operation They Actually Need |
| :--- | :---: | :--- |
| **UI labels, chips, tabs, table headers, status/enum badges, translated labels (`$t('files')`)** | **51%** *(+ huge share of CSS `.capitalize`)* | **Contextual UI / Heading Transform** (`titlecase-firstword` in most locales; `titlecase-words` only where appropriate) |
| **API/DB phrases (`weather[0].description`), Go/Rust `error.message` toasts, transcripts, prose** | **14.5%** | **Sentence-Initial Transform (`titlecase-firstword`)** with `trailingCase: 'unchanged'` and locale character tailoring |
| **Person & place names (`nombre`, `prenom`, `isim`)** | **6.5%** | **`no-change`** (do not case-normalize names; use UTS #35 Part 8 `initialPattern` for initials) |
| **Direct `Intl` / date-library outputs (`DateTimeFormat`, `DisplayNames`, `RelativeTimeFormat`)** | **~1% direct**<br>*(~10–15% file ceiling + widespread CSS)* | **CLDR `<contextTransforms>` (`standalone`, `ui-list-or-menu`, `beginning-of-sentence`, `middle-of-sentence`)** |
| **Code / identifier generation (`PascalCase`, `on${Key}`)** | **26%** | ASCII `s[0].toUpperCase() + s.slice(1)` *(already works)* |

> **Key Takeaway:** Putting `DisplayContext` *only* on `Intl` formatters (`ecma402#355`) solves <10% of JS call sites. **We must support the Two-Phase Model across CSS, JS strings, and `Intl`.**

## How CLDR, ICU4C, and ICU4X Model the Two Phases

<div class="columns">
<div>

### Phase 1: CLDR `<contextTransforms>` (UTS #35)
- Stores strings in `middle-of-sentence` form.
- Maps `(locale, usage_category) × (uiListOrMenu | stand-alone | beginning-of-sentence)` $\to$ `titlecase-firstword` or `no-change`.
- **Tiny data footprint:** Just a few bitflags per locale (not megabytes of grammar data).
- *Note:* ~20 European locales in CLDR need missing flags audited (e.g. `pt` months, `pl`/`hu`/`ro` menu language endonyms).

</div>
<div>

### Phase 2: `ICU4X TitlecaseMapper` / `ICU4C`
- Executes `titlecase-firstword` on a single span with:
  - **`TrailingCase::Unchanged`** (`U_TITLECASE_NO_LOWERCASE`)
  - **`LeadingAdjustment::Auto`** (skips `«`, `¿`, `U+2068`; keeps `"49ers"` and Dutch `"'s-Gravenhage"` intact)
  - Full `Titlecase_Mapping` + `nl`/`tr`/`el`/`lt`/`ka` tailoring.
- **Zero word-segmenter (`BreakIterator`) cost** when applied to the first word of a string!

</div>
</div>

## Solution Track 1: Context-Aware & First-Word Transforms in CSS

How can CSS (`css-text`) help authors do the right thing in both Phase 1 and Phase 2?

<div class="columns">
<div>

### 1. Phase 1: Contextual `text-transform` Keywords
Instead of authors hardcoding `text-transform: capitalize` on headings, menus, and chips:
- Explore **locale-adaptive contextual values** (e.g. `ui-title` / `ui-menu` / `standalone`):
  - In `lang="en"`, a title transform can apply English Title Case (`titlecase-words`, skipping stop words).
  - In `lang="fr" | "es" | "no" | "ru"`, it applies Sentence Case (`titlecase-firstword`).
  - In `lang="ka"` (Georgian) or where CLDR says `no-change`, it leaves text untouched!

</div>
<div>

### 2. Phase 2: `text-transform: first-word` / `sentence` (`csswg-drafts#8893`)
- Direct declarative primitive for `titlecase-firstword`:
  - Uses Unicode `Titlecase_Mapping` + `TrailingCase::Unchanged` + `LeadingAdjustment::Auto`.
  - **Works on inline elements (`<span>`, `<a>`, `<label>`)** as well as blocks — eliminating `::first-letter` hacks and Greek *tonos* bugs.

</div>
</div>

---

## Solution Track 2: Contextual Capitalization in `Intl` (`tc39/ecma402#355`)

For nouns whose Phase 1 decision depends on lexical category (months vs. weekdays vs. languages vs. relative time vs. currencies), **only `Intl` knows the category**:

```js
// Standalone calendar header:
new Intl.DateTimeFormat(locale, {
  month: 'long',
  year: 'numeric',
  capitalization: 'standalone', // 'middle-of-sentence' | 'beginning-of-sentence' | 'ui-list-or-menu' | 'standalone'
}).format(date);
// es -> "Septiembre de 2026"
// sv -> "september 2026" (respects Swedish no-change!)

// Language picker menu:
new Intl.DisplayNames(['fr'], {
  type: 'language',
  capitalization: 'ui-list-or-menu',
}).of('es-ES');
// -> "Espagnol d’Espagne" (vs "espagnol d’Espagne" in middle-of-sentence)
```

- Resolves the Chrome vs. Firefox/Safari `Intl.DisplayNames` divergence by specifying `'middle-of-sentence'` as the default.

---

## Solution Track 3: Unblocking JS Case Mapping (`tc39/ecma402#294`)

How do we fix the **90%+ of JS call sites** that transform non-`Intl` strings (weather/API text, error toasts, `<title>`, `<option>`, `aria-label`, MF2 messages) while addressing browser-vendor concerns?

<div class="columns">
<div>

### Supporting Both Phases in JS
- **Phase 1 + 2 (Context-Driven):**
  Allow transforming arbitrary strings in a locale according to a context (`'beginning-of-sentence'`, `'ui-list-or-menu'`, `'standalone'`).
- **Phase 2 Building Block (`titlecaseSegment` / `capitalizeFirst`):**
  Single-span titlecasing with `leadingAdjustment: 'auto'` and default **`trailingCase: 'unchanged'`**, composable with `Intl.Segmenter`.

</div>
<div>

### Resolves All 4 TG2 Vendor Objections
1. **Why not CSS-only?** Non-CSS sinks (`<title>`, `<option>`, `aria-label`, `<canvas>`), MF2 composition, and a11y/clipboard integrity.
2. **`MacDonald` preserved:** Default `trailingCase: 'unchanged'` never lowercases `"MacDonald"`, `"iPhone"`, or `"España"`.
3. **Zero `BreakIterator` regression:** Single-span default avoids Blink's 4.3% Speedometer 3 regression (`crbug.com/420998400`).
4. **Shared engine fast-path** with CSS `text-transform` and `Intl`.

</div>
</div>

## Summary: Matching Each Use Case to the Right Tool

| Real-World Use Case (from GitHub Study) | Broken Code Today | Proposed Platform Solution |
| :--- | :--- | :--- |
| **Declarative headings, UI chips, badges, inline `<span>`s** (`$t('...')`, status labels) | `text-transform: capitalize` (forces English `titlecase-words` onto `fr`/`es`/`no`) or `::first-letter` | **CSS `text-transform: first-word` / `sentence` (`#8893`) & contextual `text-transform` keywords** |
| **`Intl` dates, months, weekdays, languages, relative time in headers & menus** | `cap(date.toLocaleDateString(...))` or CSS `.capitalize` (ignores `sv`/`fr`/`cs` `no-change` rules) | **`Intl` `{ capitalization: 'standalone' \| 'ui-list-or-menu' \| ... }` (`ecma402#355`)** + CLDR data audit |
| **Non-`Intl` strings in JS, toasts, API phrases, MF2, `<title>`, `<option>`, `aria-label`** | `s.charAt(0).toUpperCase() + s.slice(1)` (breaks `ka`, `nl` `IJ`, `tr` `İ`, surrogates, `«`/`¿`, `U+2068`) | **JS Context / First-Word Segment Capitalization Primitive (`ecma402#294`)** |
| **Person names & initials** (`nombre`, `prenom`, `isim`) | `name.split(' ').map(w => w[0].toUpperCase() + w.slice(1).toLowerCase())` | **Do not case-normalize names (`no-change`)**; use **UTS #35 Part 8 (`initialPattern`)** for initials |

# Discussion Questions for the Breakout

1. **Two-Phase Alignment:** Do we agree on separating **Phase 1 (Contextual Decision)** from **Phase 2 (Transform Execution)** across CSS and JS?
2. **CSS (`css-text`):** Can we advance `text-transform: first-word` / `sentence` (`#8893`) and explore **locale-adaptive contextual keywords** (`ui-title`, `ui-menu`, `standalone`)?
3. **JS & `Intl` (`#355` & `#294`):** Can we advance `{ capitalization }` on `Intl` formatters (`#355`) and a shared first-word / segment primitive (`#294`, `trailingCase: 'unchanged'` default)?
4. **CLDR Upstream:** Auditing missing `<contextTransforms>` flags across European locales and adding Irish (`ga`) / Dutch elision (`'s-`) rules.
